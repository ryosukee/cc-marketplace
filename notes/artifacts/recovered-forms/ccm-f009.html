HTML 雛形のサイド空間: ハイブリッド案

今見ているのはハイブリッド案（案 B の根拠並置と案 C の脚注を、同じ 1 本の rail に統合）。同じ内容を別の組み方にしたページ: 案 A 設問並置案 C 脚注維持
設問は 3 ページとも同じ。どのページから答えても構わない。

HTML 雛形の作り直しの一環。情報デザインの外部調査で、HTML がターミナル出力や markdown に対して持つ優位は「操作できること」ではなく「本文カラムの外の空間を使えること」だと分かった。現行の雛形はその空間を脚注置き場にしている。使い道を決め直したい。

結論: 外の空間に 1 本の rail を置き、その節の判断の根拠とその節から参照される脚注を両方入れる。案 B の弱点だった「脚注の固定表示を失う」がこれで解消する。

決めること: 3 件。

  • 設問 1 サイド空間に何を置くか（ハイブリッド / 案 A / 案 C）
  • 設問 2 分離の基準を「判断に使うか」で引き直すことの承認
  • 設問 3 op-review 節を今回いじるか、T4 へ送るか

読み方: 3 案を見比べるのが目的なので、まず上のリンクで 3 ページを行き来してほしい。中身は同一で、組み方だけが違う。説明 1 と 2 は 3 ページで共通なので、2 ページ目からは読み飛ばしてよい。

説明 2 現行雛形は、判断に使う情報を本文から遠ざけている

現行の skill には、判断の根拠を本文から分離せよという規定が 4 箇所ある。「根拠・詳細は表直下の補足リストか脚注へ出す」「出典・長い補足を本文の括弧書きで埋め込まない」「脚注へ逃がしたら」「参考資料へ隔離」。

加えて雛形は、ワイド画面で脚注 #fn-set を本文カラムの右に固定表示する。分離した情報を、外の空間という最も目立つ場所に置いている。近接とは逆向きの設計になっている。

この節の決め手

判断に使う数値をどこに置くと読まれるかの実測では、本文中に括弧で併記した場合の到達率が 66%、別表が 39%、tooltip が 40%（n=924）1。

現行の指示はこの結果と逆を命じている。脚注へ送るべきは、判断に使わない出典・再現手順・生データだけになる。

案 B 単独では脚注の固定表示を失うのが代償だった。rail に同居させると場所の取り合いが起きないので、その代償が消える。

案 A は設問と比較表を並べるので form での効きは最大だが、設問の無い report では空間が余り、雛形に form 専用の分岐が増える。

案 C は変更が skill の文面だけで済む。ただし表 1 で唯一未実装の介入を、未実装のまま残す。

説明 4 レイアウト崩れの原因と直し方

表がサイドパネルの下に潜る不具合があった。原因は幅の計算が 2 系統に分かれていることで、配布中の templates/page.html にも同じ不具合がある。

表は min(100vw - 432px, 1100px) でビューポート幅から張り出す一方、サイドパネルは left: calc(50% + 348px) に固定されている。表の幅は 1100px で頭打ちになるため、ビューポートが 1532px を超えると表の右端が中央 + 550px まで伸び、中央 + 348px から始まるパネルの下へ約 200px 潜る。

この案では張り出しをやめ、本文 640px とサイド 310px を CSS グリッドの列にした。サイド列が場所を占有するので、構造上重なりようがない。表は本文カラムの中で横スクロールする。

この節の決め手

ビューポート幅からの張り出しと固定配置の併用は、幅の計算が独立しているため必ずどこかの画面幅で衝突する。片方を直しても別の閾値で再発する。

グリッドなら列幅の合計が確定するので、画面幅に依存しない。代償は表が 640px に収まることで、広い表は横スクロールになる。

設問 2/3 分離の基準の引き直し

現行は「根拠・詳細は脚注へ」と情報の種類で分離している。これを「判断に使うか」で引き直す案。判断に効く数値・根拠は本文中に括弧で併記し、脚注へ送るのは出典・再現手順・生データだけにする。

参考資料（判断には不要）

回答には要らない。実装の差と申し送り。

  • ハイブリッドの実装は CSS のみ。1120px 以上で main を 978px（640 + 28 + 310）にし、節を grid-template-areas: "bd rail" の 2 列グリッドにする。rail は position: sticky でその節の高さの範囲だけ追従する
