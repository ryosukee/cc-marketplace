設問は全ページ共通。どのページから答えても構わない。

HTML 雛形の作り直しの一環。情報デザインの外部調査で、HTML がターミナル出力や markdown に対して持つ優位は「操作できること」ではなく「本文カラムの外の空間を使えること」だと分かった。現行の雛形はその空間を脚注置き場にしている。使い道を決め直したい。

結論: 外の空間には、判断の根拠を本文の真横に置く（案 B）。推奨の理由は、近接の効果量が他の介入の 2 倍近くあり、form と report の両方で効くため。

決めること: 4 件。

  • 設問 1 分離の基準を「判断に使うか」で引き直すことの承認
  • 設問 2 サイド空間に何を置くか（3 pane / ハイブリッド / 案 A / 案 C）
  • 設問 3 op-review 節を今回いじるか、T4 へ送るか
  • 設問 4 デザインの方向

読み方: 3 案を見比べるのが目的なので、まず上のリンクで 3 ページを行き来してほしい。中身は同一で、組み方だけが違う。説明 1 と 2 は 3 ページで共通なので、2 ページ目からは読み飛ばしてよい。

説明 1 効くのは配置であって、操作させることではない

読解の成績を上げる介入を効果量の大きい順に並べた表。最上行の近接だけが雛形で未実装のまま残っている。

表 1 介入と効果量（Hedges の g）
介入効果量雛形での実装
関連要素の近接g=0.74未実装（この設問の対象）
強調g=0.43実装済み（tr.key、mark）
余分の除去g=0.33実装済み（参考資料への隔離）
操作を握らせるg=0.05投資しない

静的なページと操作できるページを比べた実験では、理解度に有意差が出なかった（操作を握らせる効果は g=0.05）。操作機構を足しても読み手の理解は上がらない。効果量が最大の近接（g=0.74）は強調（g=0.43）の 1.7 倍で、雛形で唯一手つかずの介入でもある1。

説明 2 現行雛形は、判断に使う情報を本文から遠ざけている

現行の skill には、判断の根拠を本文から分離せよという規定が 4 箇所ある。「根拠・詳細は表直下の補足リストか脚注へ出す」「出典・長い補足を本文の括弧書きで埋め込まない」「脚注へ逃がしたら」「参考資料へ隔離」。

加えて雛形は、ワイド画面で脚注 #fn-set を本文カラムの右に固定表示する。分離した情報を、外の空間という最も目立つ場所に置いている。近接とは逆向きの設計になっている。

判断に使う数値をどこに置くと読まれるかの実測では、本文中に括弧で併記した場合の到達率が 66%、別表が 39%、tooltip が 40%（n=924）1。現行の指示はこの結果と逆を命じている。脚注へ送るべきは、判断に使わない出典・再現手順・生データだけになる。

サイド空間の使い方 3 案の比較。案を分けるのは「report でも効くか」の行で、案 A だけがここで落ちる。

表 2 サイド空間の使い方 3 案
観点案 A 設問並置ハイブリッド案 C 脚注維持
外の空間に置くもの設問ブロック根拠 + その節の脚注脚注（現行のまま）

※ 近接 = 関連する情報どうしを、視線を動かさずに同時に見える位置に置くこと。ページ内リンクで飛べることは近接に入らない。クリックを挟んだ時点で同時に見えなくなるため。

案 A は設問と比較表を並べるので form での効きは最大だが、設問の無い report では空間が余り、雛形に form 専用の分岐が増える。ハイブリッドは rail の用途を出典・補足・脚注に限るので form でも report でも同じ機構が働く。案 C は変更が skill の文面だけで済む代わりに、表 1 で唯一未実装の介入を未実装のまま残す。

参考資料（判断には不要）

回答には要らない。3 案の実装の差と、出典の状態の申し送り。

  • 案 A の実装は、設問の小見出し・導入文・選択肢を 1 つの容器 #q-set に集め、1120px 以上で position: fixed にする。設問だけを移すと、何を決める設問かが panel 内で分からなくなる
  • この構成は「設問は関連するセクションの直下に置く」という現行規定と衝突する。採用するなら規定側を書き換える必要がある
  • 3 ページは下書きの保存キーを共有している。どのページで選んでも選択は 3 ページに残る
  • 情報デザインの調査結果は、数値が前セッションの引き継ぎ資料に残っているだけで、台帳に出典が記録されていない。採用する案が決まった時点で出典を台帳へ補う必要がある
