## 検出の側の穴

### 機械検査 `check-page.mjs`

18 種のうち、この語形を見るものは無い。最も近い `identifier-gloss` の正規表現は

```text
(?<![\w-])(Q\d+|PR \d+|[a-z][a-z0-9-]*\.md)(?![\w-])
```

で、「層 0」「0-A」のどちらにも当たらない。

### 提示前レビュー `page-reviewer`

`review-norms.md` の 2 条項を着手前に読むことになっているが、読ませているのは手順 (a) の
突合のためで、(a) の目的は本文に「捏造と誤引用の検出がこの段の目的」と書かれている。
造語を当てる段は (b) から (e) にも無い。条項は載るが、それを消費する工程が無い。

### skill 自身がこの穴を予告していた

`review-norms.md` の冒頭。

> clarity を agent から外したことで、文脈を知らない読者にしか気づけない指摘
> （未定義の造語など）を取りこぼす余地が残る。機械検査が拾うのは
> 識別子・文長・用語の参照マーカーの有無までで、造語そのものは判定できない。
> 取りこぼしが実際に出たら、この表を見直す。

見直しの発火条件として書かれた「取りこぼしが実際に出たら」は、この 2 枚のページで満たされている。

## 会話の返答に届く機構（2026-09-01 調査）

Stop hook は stdin の JSON で `last_assistant_message` として最終出力テキストを受け取り、
`{"decision": "block", "reason": "…"}` を返すとそのターンをやり直させられる
（8 回連続で block すると打ち切られる）。出力そのものの書き換えはできない。

裏づけは 2 つ。Claude Code v2.1.252 のバイナリ
`~/.local/share/claude/versions/2.1.252` に `last_assistant_message` の文字列が 21 件、
`stop_hook_active` が 7 件（2026-09-01 実測）。公式ドキュメント
<https://code.claude.com/docs/en/hooks.md> の Stop の節がこの 2 つを入力として記述している。

hook を実際に発火させての確認はしていない。実装の前に要る。
