### A-3. 折り返し位置（MF9 / MF10 / MF11 / MF12）の割り方

現行の「行の折り返し位置」節（行 22-28）は 2 段落。段落 1 が MF9 + MF10（核）、段落 2 が MF11 + MF12（Markdown 固有の値）。

core に足す文 1（置き場の案: 「和欧混植」節の直後に新節「原文の改行位置」。表記の層で並びが揃う。
「読み手の負荷」節に入れる案もあるが、その節は文の作り方の条項で、原文の行構成は性質が違う）:

```markdown
## 原文の改行位置

原文（レンダリング前のテキスト）とレンダリング結果が分かれる媒体（Markdown ファイル・PR 本文・HTML のソース）で、
1 行が長くて折り返すときは、句点（。）または読点（、）の直後で改行する。括弧内・修飾語句の直後・助詞の後では改行しない。
描画側が幅で折り返す媒体（ターミナル返答）には適用しない。
```

適用媒体の限定は `type-specific-screening.md:1119-1127` の判定（ターミナル返答は行折り返しの概念が違うので対象外）をそのまま条項にしたもの。

markdown-formatting.md に残す文（段落 1 を消し、段落 2 を単独で読める形にする）:

```markdown
## 行の折り返し位置

Markdown の原文の折り返しで、1 行に句読点が足りない場合は、文を 2 文に分割してから改行する。
句読点以外で切るのは、コードブロック内のコメント・URL・固有名詞列など分割不可な要素がある場合のみ。
```

判断が 1 つ残る（未特定、実装者が決める）。この形は、markdown-formatting.md だけが載った場面
（.md の短い編集で core を読まない場面）に「句読点の直後で改行する」の基準が届かない。
届かせるなら段落 1 を両方に持つ（1 回書きの原則に反する重複）。
`norm-audit-verdict-typespec.md:66-67`「分割は実装明細に文案を書く。1 条項を 2 つに割るので、割った後の文がそれぞれ単独で読めることを確かめる」に従い、どちらを採るにせよ残す文を単独で読んで確かめる。

## C. caption 相当の条項（ccm-f049 Q1）

決定（`notes/norm-refit.md:1618-1632`）: 表の直下に `※ 表 N 何の表か` の 1 行。markdown-formatting の「※ 参照」の用途に caption 相当を足す。
表の直後の行の形を lint で検知するかは範囲外。

markdown-formatting.md の「※ 参照」節（行 77-82）の書き換え案:

```markdown
### ※ 参照・表の caption 相当

用途は 2 つ。

- インラインリンクで地の文に組み込めない参照を、本文ブロックの直後に置く。
  `※ 説明文（[参照先タイトル](URL)）` の形式
- 表の caption 相当を、表の直下に置く。`※ 表 N 何の表か` の形式。N は文書内の表の通し番号
- 複数ある場合は `※` を連続して書き、各行の末尾に `<br>` タグで改行する
```

書くときの注意:

- 「表の直下」は、表の後の空行を 1 つ挟んだ次の行。表に密着させると MD058（blanks-around-tables）が落ちる
  （D と同じ lint。実測は ccm-f049 の注 10、markdownlint v0.41.1）
- 表に補足も付けるときは caption 行を先、補足を後にする。core「表」節「詳細は表の直下の補足に出す。
  媒体が脚注・補足の別枠を持つならそちらへ出す」と両立させるための順序。順序の指定を条項に書くかは未特定
- 「使い分け」の表（A-2）に行を 1 つ足す: `| 表の caption 相当 | ※ 表 N … |`
- 例を 1 つ足すなら:

```markdown
| 観点 | 案 A | 案 B |
| --- | --- | --- |
| 手間 | 小 | 大 |

※ 表 1 案 A と案 B の比較
```

core との整合:

- core「冗長の排除」の 2 項目め「何の図表かはキャプション（または表の直下に置くそれに相当する 1 行）が担う」が
  この形を前提に書かれている（ccm-f038 設問 5c、ccm-f049 の本文）。core 側の変更は無し
- 「何の表か」を本文のリード文で言わないという規範は core が持つ。markdown-formatting には形式だけを書き、
  リード文の禁止を再記述しない
- HTML 側（`html-communication/SKILL.md:320`「`caption` は表の下に置く」、雛形 `<caption>表 1 何の表か</caption>`）と
  文言の形「表 N 何の表か」が揃う。※ が付く分だけ Markdown 固有

自己適用（未特定）: この条項を入れると、markdown-formatting.md 自身の「使い分け」の表と、
rules 配下の他の表にも `※ 表 N` 行が要ることになる。PR 2 で rules 配下の既存の表に caption 行を付けて回るかは plan に無い。

## D. 余白の条項（ccm-f049 Q2）

決定（`notes/norm-refit.md:1623-1629`）: B と C の両方。markdown-formatting には lint が検査する形の実体、
core の「読み手の負荷」には媒体非依存の条項。core 側は「判定基準の無い抽象規範に戻さない」。
ユーザーの言葉は「適度な余白で負荷を減らすべきなのはそう」。

### D-1. markdown-formatting.md（「改行」節を「改行・余白」に戻し、1 項目足す）

```markdown
## 改行・余白

- 明示的な改行には `<br>` タグを使う。末尾スペース 2 つによる改行は使わない
    - 末尾スペースは不可視で、エディタの trailing whitespace 除去や Claude の Edit ツールで消されやすい
- 表・コードブロック・箇条書きの前後には空行を置く。markdownlint の MD058（表）/ MD031（コードブロック）/
  MD032（箇条書き）が検査する
```

根拠: この repo の `.markdownlint.jsonc` は MD058 / MD031 / MD032 を無効化しておらず（既定で有効）、
ccm-f049 の注 10 で 2026-08-25 に実測済み（表・コードブロック・箇条書きの直後に文を密着させると 3 つとも error）。
旧 MF8 の「`<br>` で余白」は判定基準を書けないので戻さない（ccm-f049 の設問 2 の前提文）。

### D-2. core「読み手の負荷」節（「1 つのブロックの分量を軽く保つ」の直後に 1 項目）

```markdown
- 種類の違うブロック（段落・箇条書き・表・コード）が隣り合う境界には、余白（空行・段落間隔）を置く。
  判定基準: 隣り合う 2 つのブロックの種類が違うのに、間に区切りが無い箇所があるか
```

既存条項との関係:

- 既存「1 つのブロックの分量を軽く保つ。長くなった段落は、短い文と箇条書きに割る」はブロックの中の分量を扱う。
  新条項はブロックの境界を扱う。同じ「密度」の問題を、中と境界の 2 面から規定するので重複ではない
- 判定基準を「ブロックの種類が違う境界」に限定した理由: 旧 MF8「情報密度の高いブロック」は密度の閾値を書けない。
  種類の境界は機械的に数えられ、Markdown では D-1 の lint と 1 対 1 に対応する
- 台帳の文言「適度な余白で読み手の負荷を減らす」をそのまま条項にする案は、「適度」の判定基準が無いので採らない
  （決定の「抽象規範に戻さない」に反する）

書き方は実装時に吟味すると決定にあるので、この文は案。変えるなら判定基準の 1 文を保つ。
