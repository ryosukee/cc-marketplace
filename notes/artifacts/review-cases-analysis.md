## 4. データの形の案

事例（指摘 1 件）のフィールド: id（型に依存しない通し番号）、legacy_ref（移した分の旧番号）、title、pointed_at、repo / session_repo、
doc_kind（軸 F）、location（path・line・at_commit）、span_kind（軸 E）、writer（claude / gemini / human / unknown）、
provenance（human_review / review_agent / claude_sweep / op_review_with_user）、before_text と before_verbatim、
status（fixed / unfixed / removed_with_block / withdrawn）、confidentiality（public / private / company）、context、notes。

まわりのテーブル:

- thread（channel・external_id・repo・pr・branch）
- utterance（thread・seq・speaker・role・逐語の text・at）
- finding_utterance（1 つの発言を複数の事例へ分けた範囲）
- revision（修正の段階ごとの after・逐語か・直し方・commit・差し戻した発言）
- label（軸・値・主か・誰が振ったか・score・分類の版）
- pattern と finding_pattern（型。名前・単位・説明・状態）
- relation（re_pointed / same_utterance / recurrence / caused_by_fix / same_event）
- norm_ref（補記が名指しする規範の条項。任意）

単位の規則: 同じ欠陥を直した後の再指摘は revision の段階を増やす。別の欠陥なら新しい事例にして re_pointed で結ぶ。
いまの事例集はこの 2 つの形を混ぜている。
