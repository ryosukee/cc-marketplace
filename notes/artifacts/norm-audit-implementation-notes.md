# 実装時の申し送り

判定ファイル 4 本から出た、実装で踏む注意を 1 本にまとめたもの。
判定そのものは `norm-audit-verdict-*.md` にある。

計画を立てるときの入力になる。個々の申し送りは、実装の順序か作業単位のどちらかを縛る。

## 順序を縛るもの

先にやらないと後の作業が壊れるもの。

### 1. DG40 の本文化を AQ 廃止より先にやる

`html-communication/SKILL.md` の「回答の受け取り」節は ask-with-choices への参照で
実装されている（HC266）。AQ を先に消すと、回答後のフロー（解釈まとめ → プラン提示 →
自由入力での最終確認）が消える。AQ36 の内容を HC 内へ本文化してから AQ を消す

### 2. `core` へ移す条項のうち、保持規則 L1 へ統合するものをまとめて移す

DG6（省略の禁止）・DG9（ヘッジ保持）・DG17（曖昧表現の排除）が同じ保持規則へ
統合される指定を持つ。別々に移すと同じ規則が 3 箇所に分かれる

### 3. 詳細規範を作ってから `markdown-formatting.md:9-10` の参照文を直す

現在は「japanese-text-writing skill に従う」と書いてあるが、その skill は解体される。
参照先のパスが存在してから直す

## 作業単位を縛るもの

同じ節を複数の作業が触るので、範囲を限定する必要があるもの。

### 4. AskUserQuestion の除去は言及行だけに限定する

impl-spec の「質問の原則」「品質基準」節には DG17 系の条項（曖昧表現の排除・検証可能性）が
同居している。節ごと消すと巻き込む。**対象は 16 箇所**（旧明細の 18 は古い観測値、
実測 2026-08-20）

### 5. SS18 / SS55 の字句を簡素化する

「AskUserQuestion は使わず、テキスト出力のみ」から、道具名指しの否定を落として
「テキスト出力のみ」にする。ツールが消えた後は前半が意味を失う

### 6. HC5 の字句から AQ への参照を落とす

「レンダリングバグ修正までは AskUserQuestion を使わず…ask-with-choices 冒頭の警告参照」の
うち、参照部分が切れる。基準だけ残す

## 文面を縛るもの

移すときに文面を変える必要があるもの。

### 7. DD6 に媒体条件を 1 文足す

「決め手の観点を本文で名指しする」は、HC168「「決め手」という語を使わない」と
矛盾して見える。「媒体がハイライト等の視覚表現を持つ場合はそちらに委ねてよい」を足す

### 8. RD9 を MF へ移すとき条件付きにする

「詳細は表の直下の補足に出す」をそのまま移すと、pane を持つ媒体（HTML の 3 pane）の
規範と衝突する。「表の直下か、媒体が別枠を持つならそちら」にする

### 9. DG13 の例外根拠は一般化して書く

「固有名を本文に出さない」の例外を core に書くとき、handover を名指しすると
関心事の分離（DG7）に反する。「再開・再現目的の文書では識別子は情報そのもの」と書く

### 10. EW14 は単独で述部を欠く

抽出で 1 文が EW14 / EW15 に割れており、EW14 だけでは「〜にしない」の述部がない。
解説・読み物の統合時に文を繋ぐ

### 11. SK3 の reference 列を貼り替える

種別判定表が旧 5 ファイル構成（参照 / 判断 / 論文 / 解説 / 読み物）を指している。
新 4 ファイル構成（core + 参照 + 判断 + 読み物）へ直す

### 15. AW1 の継承宣言を書き換える

現行は `academic-writing.md:10`「[判断文書の規範](./decision-docs.md)（結論先行・事実と
解釈の峻別・エビデンス）を前提に、以下を追加適用する。」。論文節を判断ファイルの末尾へ
移すとリンク先が自ファイルになり、文が成立しない。「上記の判断文書の規範を前提に、
論文ではさらに次を適用する」の形へ直す

なお IMRaD（AW2・AW3）と判断文書の結論先行は衝突しない。現行の AW1 が既に結論先行を
前提として継承しており、IMRaD は節の並びの型を指定しているだけで、
アブストラクトが結論を前置きする（`academic-writing.md:15`）。突合 agent は
「実質的な衝突 2 件」と報告したが、実際に手当てが要るのは AW1 の継承宣言だけ

## 扱わないもの

### 12. GP89 は扱わない

GP88 と同一原文の重複採番（`external-citation.md:12`）。
ID は振り直さず、欠番として扱う

## 決着していないもの

判定では処遇を決めたが、実装の前に別途決める必要が残っているもの。

### 13. impl-spec の agent レビュー終了条件が旧方式のまま

cuc と session は「指摘 0 件まで繰り返さない。もう 1 度だけ」へ移行済みだが、
impl-spec 3 skill は「指摘がゼロになるか、最大 5 回に達したら終了する」。
移設前に揃えるか、移設後に idea-hub の PR 8 で揃えるかを決める

### 14. 条件ロードの穴を塞ぐ設計

`rules/markdown-formatting.md` は `paths: **/*.md` なので、PR 本文・HTML ページ・
ターミナル返答では効かない。github-pr はこれを自覚してトンマナ規範を持ち直している
（`generate-body.md:63` が理由を明記）。この穴が空いたままだと、GP / HC の
トンマナ再実装は削れない。塞ぐ設計を決めるまで該当条項は `保留`
