# 処遇判定: DG1〜DG17

`notes/artifacts/norm-audit-raw/t3-reconcile-dg1-17.md` の突合結果に対する判定。
語彙と項目は `notes/artifacts/norm-audit-raw/verdict-schema.md` に従う。

判定の主体はメインセッション。突合は agent が行い、処遇は agent に決めさせていない。

## 判定の通し方針（DG1〜17 に共通）

旧明細の処遇提案を条項ごとに検証した結果、**大枠は追認する**。理由は 2 つ。

1. 突合で 80 インスタンス中 78 件が新抽出に対応し、消滅・特定不能が 0 件だった。
   旧明細が前提にした条項の所在は現在も生きている
2. 旧明細の分類軸（汎用は core / 種別固有は種別ファイル / 媒体固有は plugin）は、
   台帳 L262-275・L236-251 で確定した層の設計と一致している

追認しないのは下記「訂正」に挙げた分だけ。

## 訂正 1: GP の「plugin に残す」は理由を差し替える

旧明細は GP9 / GP10 / GP11 / GP20 / GP32 の据え置き理由を「自己完結原則」と書いている。
実際の理由はそれだけではない。`generate-body.md:63` が明記している。

> PR 本文は `.md` ファイルではないため、Markdown 向けの整形ルールが自動適用されない。次を意識する:

`rules/markdown-formatting.md` は `paths: **/*.md` の条件ロードなので、PR 本文を書く場面では
読み込まれない。GP のトンマナ規範はこの穴を埋めている。

- 処遇: `維持`（旧明細と同じ）
- 置き先: `plugin`
- T3 との関係: `訂正`（結論は同じ、根拠が違う）
- 根拠: 自己完結原則に加えて、条件ロードの穴を埋める役割がある。
  将来この穴を塞いだとしても、自己完結原則の側が残るので据え置きは変わらない
- 失効条件: 条件ロードの穴が塞がり、かつ plugin の自己完結原則を捨てたとき

同じ穴は HTML ページ本文とターミナル返答にもある。塞ぐ設計は別に立てる（下記「保留 1」）。

## 実装時の申し送り（DG1〜17 から出たもの）

判定そのものではなく、実装で踏む注意。

1. **`markdown-formatting.md:9-10` の参照文を直す。** 「japanese-text-writing skill に従う」と
   書いてあるが、その skill は PR 1 で解体される。参照先を新しい詳細規範のパスへ変える
2. **DG46 の実装（AskUserQuestion 除去）は DG17 の条項を巻き込まない。** 同じ「質問の原則」
   「品質基準」節を触るので、除去対象を AskUserQuestion への言及行に限定する
3. **`core` へ移す条項の統合順を守る。** DG6・DG9・DG17 は保持規則 L1 へ統合する指定が重なっており、
   別々に移すと同じ規則が 3 箇所に分かれる
4. **DG13 の例外根拠は一般化して書く。** handover を名指しすると DG7（関心事の分離）に反する
