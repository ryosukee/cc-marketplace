# 種別固有・判断保留・MF 媒体固有の行き先判断材料

norm-refit の 4 ファイル構成へ向けて、重複グループの判定で扱わなかった条項の判断材料を並べる。
処遇の判定は含まない。行き先候補と根拠を出すところまでで、採否は別工程で決める。

## 前提: 4 ファイル構成

台帳 `notes/norm-refit.md` L236-251（2026-08-14 f007 Q2〜Q4）で確定した構成を実読して確認した。
Q3 の確定文言は「reference 構成は案 2（core + 参照 + 判断（末尾に論文の追加適用節）+
解説・読み物の統合ファイルの 4 ファイル）。種別 5 分類は core の判定表が担う」。
reference の置き場は `rules/japanese-text-writing/references/`、入口 rule 名は `japanese-text-writing.md`。

本ファイルの行き先候補の値と、台帳の 4 ファイルの対応:

| 本ファイルの値 | ファイル | 内容 |
| --- | --- | --- |
| core | `core.md` | 媒体・文書種別を問わない共通原則 |
| reference-docs | `reference-docs.md` | 参照ドキュメント（README・手順書）の規範 |
| decision-docs | `decision-docs.md` | 判断文書（設計・調査・報告）の規範 |
| decision-docs（論文節） | `decision-docs.md` 末尾 | 論文の追加適用節 |
| narrative-docs | `narrative-docs.md` | 解説と読み物の統合ファイル |

台帳が同時に確定している、行き先の判断に効く前提が 2 つある。

- L289-299（2026-08-15 f008 Q7/Q8）: 分類ごとの規範の差は読み物 reference にだけ例外として書く。
  読み物 reference を読まない限り適用される規範がほぼ論理的なテクニカルライティングの規範になるよう配置する。
  論文・解説・判断・参照の各 reference には分類固有の例外を持たせない方向。
  この前提の下では、AW・EW の「論理的な正確さ」系の条項は core へ引き上がる候補になる
- L185-188（2026-08-14 f006 Q1）: japanese-text-writing plugin は解体する。
  SK 条項の現在地である SKILL.md は消えるので、SK 条項は 4 ファイルのいずれかに移すか、
  入口 rule（最小構成 2 節）へ入れるか、消えるかのいずれかになる

## C 群: MF の媒体固有 32 件

`rules/markdown-formatting.md` の frontmatter は `paths: - "**/*.md"` の条件ロードで
（実読で確認、ファイル 1-4 行目）、markdown ファイルを扱うときしか読み込まれない。
PR 本文・HTML ページ・ターミナル返答では効かない。
`plugins/github-pr/skills/create/references/generate-body.md:62` がこの穴を明示している。

> "PR 本文は `.md` ファイルではないため、Markdown 向けの整形ルールが自動適用されない。次を意識する:"
>
> 出典: `plugins/github-pr/skills/create/references/generate-body.md:62`

行番号は実読で確認した。`notes/artifacts/norm-audit-raw/README.md` は同じ文を `:63` として引いており、
1 行ずれている。

判定の値は 2 つ。

- markdown 記法固有: 規定の対象が markdown（または GFM）の記法そのもので、
  記法が存在しない媒体には適用先がない
- 記法一般: 規定の対象が情報の配置・参照・文字の選択で、
  markdown 以外の媒体（HTML ページ・PR 本文・ターミナル返答）でも同じことが起きる

判定に効く区別が 1 つある。PR 本文・Issue 本文・commit message は GitHub 上で GFM として
レンダリングされるので、記法自体は通用する。届かないのは記法ではなく rule のロードで、
「記法固有だが媒体には効くはずの条項」が存在する。
一方 HTML ページ本文とターミナル返答は markdown 記法そのものが通用しない（ターミナル返答は
ハーネスの描画に依存し、`> [!NOTE]` や `※` の運用は再現されない）。
