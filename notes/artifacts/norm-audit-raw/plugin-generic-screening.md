# plugin 側の汎用条項と既存規範の突合

対象は `norm-audit-raw/` の各ファイルで `- 性質: 汎用` が付いた条項のうち、
重複グループの判定で既に扱った ID を除いた 98 件（SS 39 / HC 19 / SK 9 / GP 8 / FN 8 / MF 7 / UC 5 / JR 3）。
機械抽出で数え、依頼の件数と一致した。処遇は決めない。分類と移設先候補の提示までを行う。

突合先は 15 ファイル（`rules/` 直下 10 本、`rules/references/notes-format.md`、
japanese-text-writing skill の SKILL.md と references 5 本、`.claude/rules/` 3 本、計 1033 行）。
全文を通読して突合した。各エントリの「突合」欄には、その条項で見た範囲と手がかりにした語を書く。

## 読むときの前提

- JR / UC / MF は `rules/` 直下のファイル自身に属する条項で、突合先と出所が同じ。
  自ファイルとの一致は突合にならないため、自ファイルを除いた 14 ファイルに対して突合した。
  この 3 群の `既存なし` は「他の場所に重複が無い」を意味し、その条項が実体であることを示す
- `移設先` の語彙は依頼の 6 語（`core` / `判断` / `参照` / `読み物` / `条件` / `据え置き`）に従う。
  振る舞い規範（実行報告・承認・反復の打ち切り等）は執筆規範の 5 層に対応する置き場が無いため
  `据え置き` を選び、理由に「どの層にも家が無い」ことを書いた

## 突合中に見つかった、既存規範との矛盾

判定の材料になるため先に出す。

| 条項 | plugin 側 | 既存規範 |
| --- | --- | --- |
| HC154 | 「読み方」の節を書かない | `decision-docs.md:16`「冒頭に地図を置く: 目的 / 決めること / 読み方」、`SKILL.md:52`「冒頭に地図（目的、扱う範囲、読み方）を置く」 |
| HC221 | 無ければ作ってよいが、初出で必ず定義する | `SKILL.md:99`「新しい概念に名前を付ける前に既存の一般用語を探し、独自語を作らない」（条件付き許可ではなく全面禁止） |

もう 1 つ、条件ロードの穴に該当するものがある。MF13 / MF14 / MF15 / MF16（和欧混植）は

対応する既存規範 `markdown-formatting.md:16` が HTML の場面では効かない。

## 汎用でない

### MF11

- 原文: 長文 1 行に句読点が足りない場合は、文を 2 文に分割してから改行する。
- 位置: rules/markdown-formatting.md:32
- 理由: 発動の契機が `.md` ソースの行折り返しに固有。直前の `markdown-formatting.md:29-30`「1 行が長くて折り返しが必要な場合、句点（。）または読点（、）の直後で改行する。」を受けた条項で、句読点の位置で改行できないときの回避手段として書かれている。HTML 本文とターミナル返答にはソース行の折り返し位置という概念が無く、この契機が成立しない。分割という操作そのものは `SKILL.md:103`「一文を長くしすぎない。接続の多い長文は文を分ける」が既に汎用の形で持っている
