### 条件ロードの穴を埋めるための再実装がある

`rules/markdown-formatting.md` の frontmatter は `paths: - "**/*.md"`。
markdown ファイルを扱うときしか読み込まれないので、PR 本文・HTML ページ・ターミナル返答を
書く場面では効かない。

github-pr がトンマナ規範を持ち直しているのは、この穴を自覚して埋めているため。
`plugins/github-pr/skills/create/references/generate-body.md:63` が理由を明示している。

> PR 本文は `.md` ファイルではないため、Markdown 向けの整形ルールが自動適用されない。次を意識する:

この型の重複は「基底 rule にあるから plugin から削る」で処理すると壊れる。
削る判定を出すなら、先に読み込みの穴を塞ぐ設計が要る。
同じ穴は html-communication（HTML の本文）とターミナル返答にもある。

| DG | HC の現行 | 詳細規範の現行 |

旧明細が引いていた当時の HC の文言は「根拠・詳細は表直下の補足リストか脚注へ出す」（DG23）と
「決め手の行はハイライトし、リード文で行名を名指しする」（DG24）。どちらも現在は逆を向いている。

判定で決めること: どちらへ揃えるか。HC 側の反転には理由がある（3 pane で脚注と補足が本文と

詳細規範側を単純に HC へ合わせると、pane を持たない媒体で根拠の所在が消える。
