# 処遇判定の書式

条項ごとの処遇を記録するときの語彙と項目。抽出が全部揃ってから一度に判定するため、
書式を先に固定する。判定を始めてから項目を足すと全件の見直しになる。

## 置き先の語彙

norm-refit で確定済みの層に対応させる。層の定義は台帳 `notes/norm-refit.md` L262-275 と L236-251。

| 語 | 実体 | 使う条件 |
| --- | --- | --- |
| `入口` | `rules/japanese-text-writing.md`（常時ロード、2 節・約 20 行） | タイプ判定と数行返答の最小規範だけ。ここを増やさない |
| `core` | `rules/japanese-text-writing/references/core.md` | 媒体・文書種別を問わない汎用規範の実体 |
| `参照` / `判断` / `読み物` | 同 `references/` の種別ファイル 3 本 | その種別に固有の具体形。汎用文は core に寄せ、固有部分だけ残す |
| `条件` | `rules/markdown-formatting.md`（`paths` 付き） | markdown の記法に限って効くもの |
| `plugin` | 各 plugin の skill 本文 | 媒体固有。その skill でしか意味がない |
| `T4` | 後続工程へ送る | 情報デザイン norm 48 本の置き場など、T4 で決めると確定済みの範囲 |
| `後続` | タスク #7 へ送る | 今回の対象外ファイルに属する、または今回の判定材料が足りない |
| `移設先` | idea-hub の PR 8 で `product-workflow` へ同行させる | impl-spec の条項のうち、cc-marketplace 側へ引き上げないもの |

## 処遇の語彙

| 語 | 意味 |
| --- | --- |
| `維持` | いまの場所にそのまま残す |
| `移設` | いまの場所から消し、別の層へ実体を移す。移設先を必ず書く |
| `統合` | 他の条項と 1 本にまとめる。統合先の条項 ID を必ず書く |
| `削除` | どこにも残さない。削ってよい理由を必ず書く |
| `退避` | `paths` 付きの条件ロードへ移す |
| `保留` | 今回は決めない。決めるのに何が要るかを必ず書く |

## エントリの項目

条項 1 件につき 1 エントリ。

- **ID**: 抽出の ID（`JR3` 等）
- **処遇**: 上の 6 語から 1 つ
- **置き先**: 上の 7 語から 1 つ。`維持` と `削除` では現在地を書く
- **T3 との関係**: `追認` / `訂正` / `新規`（T3 明細に対応が無い） / `対象外`
- **根拠**: 1〜2 文。他の条項との関係で決まるなら相手の ID を書く
- **失効条件**: その判定が崩れる条件が言えるなら書く。言えないなら行ごと省く

## 判定の順序

1. 重複グループに属する条項を、グループ単位で先に決める。実体を 1 箇所に決め、他をその参照か削除にする
2. 重複していない条項を、単独で決める
3. `保留` になったものを集め、決めるのに要る材料を一覧にする

グループ単位を先にするのは、片側の処遇が反対側に依存するため。
単独条項から始めると、後で重複が見つかったときに決め直しになる。

## impl-spec の条項は扱いが違う

idea-hub の確定台帳 Q43 / Q109 / Q110 により、impl-spec は norm-refit の完了後に
`product-workflow` へ改名して product-boilerplate へ移設される。実装計画の PR 8 が
`impl-spec@cc-tools` の uninstall と `enabledPlugins` からの除去まで定めているため、
cc-marketplace 側には残らない。

- 他の plugin（HC / GP / SS）は cc-marketplace に残るので `plugin` が使える
- IS は `plugin` を使わない。cc-marketplace へ引き上げるか、`移設先` へ送るかの二択になる
- norm-refit は移設の上流（Q110）なので、IS の汎用条項を user global 側へ引き上げる機会は今回が最後

impl-spec の内部重複（原文完全一致 36 種・91 条項）は norm-refit で畳まない。
3 skill を抱えたまま統合される以上、畳んでも PR 8 の統合形へ組み直される。
PR 8 への申し送りとして記録する。
