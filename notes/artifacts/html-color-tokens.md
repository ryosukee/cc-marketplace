# HTML ページの配色トークン設計

調査日 2026-08-17。ライトとダークの両方で、複数の意味的役割を混同なく符号化する配色の設計。
コントラスト比はすべて WCAG 2.2 の定義式で計算した実測値。

## 結論

原因は「ダークで濃淡が足りない」ことではなく、`--fg` 1 個を**本文テキストと構造の線の両方**に
使っていたこと。見出しの標識・決め手の行・現在地バーはいずれも `--fg` で描かれており、
本文テキストとの相互コントラストが**ライト / ダークとも 1.00**（同一色）だった。

ライトで区別できていたのは濃淡が効いていたからではなく、暗字 × 明地のほうが細部の解像が
良いため。この非対称は陽画表示優位（positive polarity advantage）として実験的に確認されている。

修正は 2 つ。

1. `--rule-strong` を新設し、「本文テキストがインクの極値、線はその手前で止まる」を
   両モード共通の不変条件にする。`--fg` との差は ΔL\* でライト 24.5 / ダーク 25.3
2. 強調 3 種（要点 / 決め手の行 / 現在地）を色ではなく**描画チャネル**で分ける。
   要点 = 語句幅の下線、決め手 = 行頭の縦罫 + 太字、現在地 = 節の面 + 罫 + ラベル

## 調査でわかったこと

### ダークで「白に近い色を強調に使う」設計が壊れる理由

- 陽画表示優位: 暗字 × 明地のほうが校正成績が良い。周囲照度・色度に依存しない。
  色コントラストは輝度コントラストの不足を代替できない（Buchner &amp; Baumgartner 2007, *Ergonomics*）
- 機構: 陰画表示では瞳孔が大きくなり網膜像が甘くなる。瞳孔径と校正成績の同時計測で確認
  （Piepenbrock et al. 2014, *Ergonomics*）
- **陽画優位は文字が小さいほど線形に大きくなる**（Piepenbrock et al. 2014, *Human Factors*）

実務上の意味: 1px と 2px の罫の差、ΔL\* 5 程度の段差は「小さい細部」にあたる。
ダークでは細部の差を輝度に載せず、太さ・幾何・面と線の別に載せる。

### 輝度以外の手段

| 手段 | 使える場面 | 限界 |
| --- | --- | --- |
| 不透明度階層（白 87 / 60 / 38%） | 文字の 3 段階 | 合成後の色が地に依存し決定的でない |
| elevation overlay | 面の階層 | 影が前提。影を使わない方針と衝突 |
| 彩度を下げた明トーン | ダークのアクセント | ライトと同一の hex を使い回せない |
| 面と線のロール分離 | 役割の区別 | Radix Colors が step 3-5 = 背景 / 6-8 = 罫線で分けている |
| 罫の太さ・字送り・太字 | 役割の区別 | 一次情報は未確認 |

Radix の 12 段が最も直接の参考になる。6 = 非インタラクティブの弱い罫、7 = インタラクティブの罫、
8 = hover の強い罫、11 = 低コントラストテキスト、12 = 高コントラストテキスト。
**罫とテキストが別ロールとして分かれている**点が、今回の `--fg` 兼用の対極。
Primer（`fgColor.*` / `borderColor.*`）と Carbon（`text-*` / `border-*`）も同型。

### 彩度の高い色がダークで滲む現象

Material Design 2 が "Saturated colors also produce optical vibrations against a dark background"
と書くが**この文自体に出典がない**。機構としては眼の縦方向色収差（青は赤より約 2 ディオプター
手前で焦点を結ぶ）が挙げられるが、陰画表示の瞳孔散大と結びつけた一次情報は未確認。

現行の dark `--accent-fill: #2563eb` は L\* 46.1 / C\*ab 80.1 で、near-black 地に置く色として
最も条件が悪い（暗く彩度が高い）。ダークでは明面 × 暗字に反転する。

### 色符号の上限

「7±2 が色にも当てはまる」は**支持されなかった**。Miller (1956) の 2.5 bit ≈ 6 は
音の高さの実験値で、同論文が引用する色相の値は 3.1 bit ≈ 8〜9。
Ware・Healey・Boynton の色数上限はいずれも一次情報に到達できず未確認。

確実に言えるのは WCAG 1.4.1 が「色を唯一の視覚的手段にしない」を A レベルで要求すること。
救済は (1) テキスト・記号・パターンの併記、(2) 明度でも 3:1 以上の差、の 2 ルート。

### WCAG の適用範囲

| 対象 | 該当 SC | 閾値 |
| --- | --- | --- |
| テキスト | 1.4.3（AA） | 4.5:1 / 大文字 3:1（大文字は 18.5px・24px bold） |
| UI コンポーネントと状態 | 1.4.11（AA） | 3:1（隣接色に対して） |
| 純粋装飾の罫線 | 対象外 | ― |
| フォーカスリング | 1.4.11 と 2.4.13 を併用 | 隣接色に 3:1 / focus 前後の同一画素で 3:1 |
| ハイライト上のテキスト | 1.4.3 | 4.5:1（測るのはテキスト対ハイライト背景） |

ダークモード専用の W3C ガイダンスは**存在しない**。APCA は WCAG 3.0 WD 本文に記載がなく、
APCA 自身も public beta と自称しており、現時点で規範性はない。

Focus Appearance は SC **2.4.13**（AAA）。2.4.11 は Focus Not Obscured (Minimum)（AA）。

### 不変条件

インクの並びが両モードで同一。`--rule` < `--control-border` < `--sub` ≲ `--rule-strong` < `--fg`。

| | light L\* | dark L\* |
| --- | --- | --- |
| `--bg` | 100.0 | 8.2 |
| `--rule` | 81.9 | 27.3 |
| `--control-border` | 54.1 | 54.1 |
| `--sub` | 39.3 | 64.5 |
| `--rule-strong` | 33.8 | 66.0 |
| `--fg` | 9.3 | 91.2 |

ダークの `--sub` と `--rule-strong` は ΔL\* 1.5 でほぼ同じ明るさに置いてある。
ダークには中間帯に 3 段を取る余地がないため、この 2 つは
「0.875em の文字」と「2〜3px の線」という**描画の違い**で区別する。
輝度で分けようとすると必ずどちらかが `--fg` に寄る。

## 役割 11 種とトークンの対応

| 役割 | 描画 | トークン | 冗長な第 2 チャネル |
| --- | --- | --- | --- |
| 本文テキスト | 文字色 | `--fg` | ― |
| 弱いテキスト | 文字色 | `--sub` | サイズ 0.875em |
| 構造の罫 | 線 1px | `--rule` | ― |
| 見出しの標識 | 左の縦罫 4px | `--rule-strong` | 位置・字送り |
| 要点の強調 | 語句幅の太い下線 | `--mark` | `font-weight: 700` |
| 決め手の行 | 行頭の縦罫 3px | `--rule-strong` | 太字・表内という文脈 |
| 現在地 | 節の面 + 左縦罫 + 上下罫の昇格 | `--surface-now` + `--rule-strong` | ラベル・`aria-current="location"` |
| 操作できるもの | 文字色 / 塗り / 輪郭 | `--link` / `--link-fill` + `--on-fill` | **下線（必須）** |
| フォーカスリング | outline 2px + offset 2px | `--focus` | 形状 |
| 状態 | 文字色 | `--ok` / `--ng` | **記号（必須）** |
| 面 | 面 | `--surface-code` / `--surface-bar` | 形状 |

見出しの標識・決め手の行・現在地は同じ `--rule-strong` を共有する。
**色では区別せず、幾何で区別する**（水平短線 / 表の行頭縦線 / 節を囲む面つき縦線）。

現在地だけが面を使えるのは、スクロール由来の画面固有の状態で印刷時に存在しない役割だから。
面が飛んでも失うものがない唯一の役割にだけ面を割り当てている。

## コントラストの実測

テキスト（要 4.5:1）は全 16 組が適合。最小はライトのリンク文字 / 現在地面で 4.69。
非テキスト（要 3:1）は全 9 組が適合。最小はライトの輪郭 / バー面で 3.61。

今回の修正点が数字に出るのは次の行。

| 組み合わせ | 修正前 | light | dark |
| --- | --- | --- | --- |
| 本文テキスト / 構造の線 | 1.00 | 2.14 | 2.09 |
| 本文 / 要点の下線 | ― | 12.84 | 5.17 |
| 本文 / 現在地の面 | ― | 15.48 | 12.49 |

`outline-offset: 2px` は要件。0 にすると塗りボタン上でリングと面が同色になり、
1.4.11 の「隣接色に 3:1」を満たさなくなる。

記号併記が必須の箇所が 2 つある。`--ok` と `--ng` は相互コントラスト 1.07 / 1.04 で
ほぼ等輝度なので、色だけでは 1.4.1 を満たさない。
リンクと弱いテキストも 1.26 / 1.01 なので、**下線は装飾ではなく要件**。

## 現在地の色（2026-08-17 追記。同日中に撤回済み）

> [!WARNING]
> この節の結論（Radix plum）は撤回した。選定に使った「既存 4 色から色相を 58 度以上離す」
> という基準に一次情報の裏付けが無く、比較対象にブラウザの既定色を入れていなかった。
> 確定した結論は縦罫 2px のリンク色の流用で、専用の色相は作らない。
> 詳細は台帳 `notes/norm-refit.md` の「現在地は縦罫 2px のリンク色」エントリ。
> 以下は経緯として残す。

### 撤回時に失効した決め手

- 「現在地だけが面を使えるのは、印刷時に存在しない役割だから」は、面をやめて線に移したことで
  前提が変わった。ただし印刷は考慮の対象外とユーザーが決定（2026-08-17）したため、
  この決め手ごと不要になった。以降、印刷を理由にした設計判断は行わない
- 役割表の「アクセント色（青）を操作できるものだけに限る」は失効した。
  確定した役割は「青 = 操作できるもの + 現在地」「地の濃淡 = 構造」「琥珀 = 本文中の要点」
  （ccm-f023 の回答 2026-08-17）。見出しの標識は無彩のまま据え置き
- 役割表の「見出しの標識」の幾何を、実装に合わせて「水平線 2px × 26px」から
  「左の縦罫 4px」へ更新した。上の短い横線から左の縦罫へ変えたときに表を直し忘れていたもの。
  色（`--rule-strong`）は当初から表のとおりで、今回そこへ戻った

### 撤回した分析（詳細は削除）

推奨は Radix plum の step 11 で、「既存 4 色の色相角から 58 度以上空く窓は 2 つだけ」
という基準から選んでいた。この基準に一次情報の裏付けが無く、比較対象にブラウザの
既定色を入れていなかったため撤回した。候補表・却下理由・plum を推した根拠は
判断に使えないので削除した。撤回の理由と確定した内容は台帳の該当エントリにある。

### 撤回後も有効な一般則

- 地 `#16181d` は L\* 8.24 / C\* 3.85 で、Radix slate の 1-2 相当。
  青寄りではあるが色温度で候補を縛るほどの偏りではない
- 色相の判定を 1 つの色空間で行わない。CIELAB は青領域で歪むので、OKLCh と HCT でも測る
- 明るいアクセントの帯は L\* 64.8-72.9、C\* 36.7-43.4。ただしこれは面と塗りの実測から
  出た帯で、細線・小文字に当てる裏付けは無い（当てて失敗したのが上の撤回）

## 却下した案

| 案 | 理由 |
| --- | --- |
| 現在地に第 3 の色相を与える | 色符号が 4 系統になる。緑は状態と衝突する。幾何で分けられる以上、色相を消費する理由がない |
| 濃淡で強調 3 段を作る | ダークで実測 ΔL\* = 0。本文が L\* 91 で天井まで 9 しか残らない |
| 現在地以外の節を `opacity` で沈める | opacity 0.62 で `--sub` が 3.27 / 2.80 に落ち 1.4.3 を割る |
| ダークの `--fg` を純白にして余地を作る | Material の high-emphasis 87% に反する。瞳孔散大と重なって滲みが増える |
| `--rule` を 3:1 まで上げる | 表の横罫が主張しすぎる。1.4.11 は純粋装飾の罫線を除外している |
| 太字を 3 段にして役割を分ける | `system-ui` で日本語ゴシックの 600 が供給される保証がない（未確認） |
| 影・elevation overlay | 影を使わない方針 |
| `oklch()` で値を書く | self-contained ページはフォールバックを持てない。設計の思考空間としてのみ使い、出力は hex |

## 未確認

設計を見直すときにだけ効く。いま対応は要らない。

- halation / irradiation がヒトの読字時に生じる機構の一次情報
- 罫の太さ・字送りをダークの階層化手段として扱った一次情報
- 細い線・小さい文字それ自身の知覚彩度を直接測定した実験値
  （同化の誘導量からの推論に留まる）
- 二色覚での見え方の実測比較。青と紫が混同しやすいことは Okabe &amp; Ito が挙げているが、
  実測値の表には到達していない
- Adobe Spectrum（repo の構造が変わり取得できず）

### 解消したもの

- 色数の上限と色コードの規定、色相角の弁別閾: MIL-STD-1472F/G/H・FAA HF-STD-001B・
  ANSI/HFES 100-2007・Healey 1996・Smallman &amp; Boynton 1990 を取得して解消した。
  「色相角で何度離す」を定める一次情報は存在しないことが確定し、
  規範的な数値基準は ΔE (CIELUV) ≥ 20 の 1 つだけだった。Ware の 12 色リストは 4 版で著者が削除
- 彩度色の「震え」と pure black 回避: Material 2 の該当文に出典が無いことを再確認。
  Apple HIG の記述も取得済み
- 1.4.11 の適用範囲（見出しの罫・現在地インジケータ・ハイライト背景）: 対象かどうかに
  関わらず、実測で 3:1 を満たすことを確認したので判定が不要になった
- `box-shadow` の印刷時の挙動: 印刷を考慮の対象外と決めたため不要
- `system-ui` の日本語フォントのウェイト供給: 太字を 3 段にする案を採らないため不要
