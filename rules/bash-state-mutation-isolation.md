# 状態変更と復旧を 1 つのコマンドに連結しない

作業ツリー・プロセス・環境の状態を変える操作とその復旧操作を、
失敗やタイムアウトしうる処理と同一のシェルコマンドに連結しない。
git stash に限らず、環境変数の一時変更・サービスの一時停止・設定の書き換えなど、
「後で元に戻す」前提の操作すべてに適用する。

- 状態変更 → 本処理 → 復旧を、それぞれ別の Bash 呼び出しに分ける
- 復旧の直後に状態確認（`git status` / `git stash list` 等）をセットで実行する
- 「まとめれば速い」という効率より、「途中で切れたら復旧が走らない」という
  シェル連結の性質と、その操作の失敗時被害を優先して評価する。
  判定基準: このコマンドが途中で死んだとき、次に打つコマンドから見えている状態は安全か

## why

シェル連結（`&&` / `;`）は途中で打ち切られると後続が実行されず、復旧だけが失われる。
実例（efso-idp セッション 2026-07-29）: `git stash && mkdocs build ...; git stash pop` を
1 つの Bash 呼び出しで実行し、build が Bash ツールの 2 分タイムアウトで打ち切られて
pop が走らず、作業ツリーが退避されたまま（差分が空のまま）検証・レビューが進みかけた。
レビュー用 subagent が検知して復元したため実害はなかったが、検知がなければ空 diff を
コミットしていた。
