# ユーザーへの報告・質問は形式を選んでから書く

ユーザーに向けた出力は、書き始める前にフリーテキスト / ask-with-choices skill / html-communication skill の
どれで出すかを判定する。フリーテキストは既定ではなく、判定の結果として選ぶもの。

## 判定のタイミング

出力を書き出す直前に判定する。ツールの結果を受け取って、そのまま最終メッセージを書き始めない。
調査・比較・検証の依頼で、着手の時点で分量が読めるならそこで決めてよい。

## 判定基準

量と性質で選ぶ。

- 数行・数点に収まる報告、単発から少数の質問: フリーテキスト
- 判断をユーザーに委ねる問いが主題: ask-with-choices skill を読み、その指示に従う
- 重厚でスクロールが必要な分量になる、比較表や長い前提説明を伴う、設問が多い:
  html-communication skill を読み、HTML ページにする

HTML にするときは、長文をそのまま HTML へ移し替えない。
結論・概要から詳細へ辿れる構造（セクション分け、比較表、出典の分離）に組み直す。
各形式の運用の正典は該当 skill にあり、この rule は入口の判定だけを担う。

## 判断の件数でも切り替える

分量とは別に、ユーザーに決めてもらう判断がいくつあるかで出し方を変える。

- 判断が 1 件: 本文の中で問う
- 判断が 2 件以上: 1 件ずつ順に出すか、HTML にまとめる。1 メッセージに並べない
- 選択肢に出てくる語は、選択肢より前に実体を書く。
  他の文書の文面をそのまま貼らない。その文書は前提を共有した読み手向けに書かれている

判定基準: そのメッセージを読んだユーザーが、最初の判断に答えるために
最後まで読む必要があるか。あるなら分割する。

## why

依頼の見た目からは形式が決まらない。質問の体裁で来た依頼が長い調査報告になることも、
調査の依頼が数行で済むこともある。出力の形が確定するのは書き出す直前なので、判定もそこに置く。

判定を置かないと、ツールの結果から最終メッセージへ流れる既定の経路にそのまま乗り、
分量に関わらずターミナルへの長文になる。
