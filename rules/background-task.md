# バックグラウンドタスクの起動方法

プロセスをバックグラウンドで起動する場合は、必ず Bash ツールの `run_in_background` パラメータを使う。シェルの `&` は使わない。`run_in_background` で起動したプロセスは `/tasks` で一覧・確認できる。

## 想定より遅いときは、再実行の前に出力を全部読む

コマンドが想定より遅い・返ってこないとき、kill して再実行する前に、そのコマンドの出力を捨てずに全部読む。

- パイプで絞っている（`| grep`、`| tail`、`| head`）なら、外して取り直す。
  絞りは成功時の出力を短くするためのもので、失敗時は捨ててはいけない情報が入る
- 標準エラーも取る。`> log 2>&1` でファイルに落として読む
- 対話的な入力を待っている可能性を先に潰す。`< /dev/null` を付けるか、
  そのコマンドに標準入力を読まない指定があるかを調べる

判定基準: いま「なぜ遅いか」を推測しているか。推測しているなら、まだ出力を読んでいない。

why: 遅さの原因を外部要因（リソース、競合、ネットワーク）に求めると、再実行と待機を繰り返すことになる。
実際にはコマンド自身が理由を出力していることが多く、絞り込みのパイプがそれを捨てている。
