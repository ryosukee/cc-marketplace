# CLAUDE.md の書き方

CLAUDE.md に何を書き、何を書かないかと、更新の時期を定める。

## 役割とサイズ

CLAUDE.md はセッション開始時にコンテキストへ読み込まれるプロジェクトガイド。
個々の作業のやり方ではなく、プロジェクトそのものの成り立ち（構造・動かし方・固有の知識）を伝える。

200 行以下に収める。超える場合は rule に分離するか、`@path` import で本文を外に出す。

why: 常時コンテキストに読み込まれるため、長いほどコンテキストを消費し、指示の遵守率が下がる。

## 書くもの・書かないものの判定

判定基準: プロジェクトの事実を伝える記述は CLAUDE.md、作業の仕方を課す規範は rule、
機能の仕様は設計ドキュメントに置く。

書くもの（例）:

- プロジェクト概要（1〜2 行）と技術スタック
- ビルド・起動コマンドと検証コマンド (lint / test)
- ディレクトリ構成の概要
- プロジェクト固有の概念と用語の概要
- 環境構成（開発 / 本番 / CI の違い）
- 既知の制約・注意事項
- 開発フローの概要

書かないもの（例）:

- 特定の言語・道具に固有の作法や規約
- 検証のやり方の詳細
- 個々の部品の設計の詳細
- 機能や振る舞いの仕様

## rule との重複を作らない

rule に詳細がある内容は、CLAUDE.md には概要 1〜2 行だけを書く。
設計ドキュメントに詳細がある内容は、概要 1〜2 行とリンクを書く。同じ内容を両方に書かない。

why: 重複すると片方だけ更新されて陳腐化し、矛盾した指示になる。

## 更新の時期

次の変更をしたら、同じコミットで CLAUDE.md も更新する。

- プロジェクト固有の概念・データの構造・用語が変わったとき
- 動かし方・確かめ方の手順が変わったとき
- rule・skill・agent の構成が変わったとき

why: 記述と実物が食い違うと、読み手はプロジェクトを誤解したまま作業を進める。
