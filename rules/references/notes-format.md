# notes 形式: タスク別一時メモの運用

[長い調査・設計では確定事項の台帳を持つ](../decision-record.md) が既定案として提案する台帳の形式。
このファイルが運用の正典で、各 repo 側には運用説明を書かない。

この frontmatter の `paths` は、どの作業にもマッチしない値を意図的に指定して
このファイルを常時ロードから外している。`paths: []` や `["**"]` に変えると常時ロードに戻るため変更しない。

## 構造

repo 直下 `notes/` の 2 層。

- `notes/README.md`: メモの一覧（ファイル / 対象タスク / 状態 / 最終更新の表）と、
  rule `decision-record.md` へのファイル名での言及だけを置く
- `notes/{task-slug}.md`: 1 タスク（またはプロジェクト）1 ファイル。他タスクの内容を混ぜない。
  ファイル内は「確定事項」（追記専用。エントリ形式は rule 本文に従う）と「作業メモ」（自由）の 2 節

## ライフサイクル

- 作成はユーザー承認後（rule 本文の手順に従う）
- タスク完了時のメモの処遇はプロジェクトの慣行に従う（正式な文書への昇格、チケット等への記録、
  そのまま削除のいずれもありうる）。いずれの場合も notes/ にファイルを残さず、README の一覧からも消す
