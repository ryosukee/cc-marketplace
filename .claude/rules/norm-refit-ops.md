## 置き場と着手手順

- 決定と計画は agent-kanban の CCM Project の Epic CCM-E4（norm-refit）にある。
  決定は CCM-E4 とその配下の作業項目の決定記録が、計画は着手する Task の作業情報と CCM-E4 の plan tree が持つ。
  着手するときは agent-kanban の skill の手順で Task に着手し、実装の前にその Task の作業情報と関係する決定記録を読む
- norm-refit の decision-record、計画、付随資料を置いていた `notes/` は、2026-10-06 に CCM-E4 へ移して消した。
  付随資料は CCM-E4 の原文記録にある。移さなかった記録（作業の記録、notes の運用の決定、解消済みの未解決課題、
  完了した段階の計画の節）は、commit `177e92e` の `notes/` から読める
- 決定は 1 件 1 記録として決定記録に残す。決めなかった範囲は保留・対象外の欄に、成立条件は存続条件と失効条件の欄に書く。
  影響範囲の欄には、反映先を「rules のどのファイルのどの節 / どの plugin / 反映なし」のいずれかで必ず書く。
  HTML skill 側で決めた規範でも、媒体を問わない内容なら共通規範を反映先に含める
  （書かないと実装時に拾われない。2026-08-25 の観測）
- 決定を変えるときは、元の決定記録を書き換えず、訂正の履歴として重ねる
- 作業の一覧（条項の一覧、横展開の対象リスト）は scratchpad に置かず、原文記録に残して作業情報の参照先から指す。
  scratchpad はセッションとともに消え、後から照合できなくなる
- idea-hub へ伝えるべきことが出たら、CCM-E4 の配下の作業項目の作業情報か決定記録に書く。
  段階 5 で idea-hub へ渡すときに、agent-kanban の IDEA Project に作業項目を作る。
  これまでの下書きは、CCM-T4 の参照先にある原文記録が持つ。
  idea-hub 側は norm-refit の全完了後に着手する

## 節目ごとの最新化

節目（PR を出した・マージした・判断が決着した・決定を変えた・段階が動いた）のたびに、
着手している Task の作業情報（完了した内容・現在地・次の行動・未解決事項）をその場で書き直す。
Task を足したときと題名を変えたときは、CCM-E4 の plan tree も同じ時点で直す。作業を積んでからまとめて直さない。

進捗レポート `ccm-r003` を続けるかは、CCM-T4 で決める。続けると決まるまでは更新しない。

決定記録と作業情報と plan tree が同じ状態を指していないと、次のセッションが古いほうを正として読む

## PR の出し方

- 実装は必ず PR にする。main へ直接入れない
- PR を出す前に、CCM-E4 とその配下の決定記録のうち前回の PR 以降に記録したもの全件を列挙し、
  反映先ごとに実装と突合する。反映済み / 未反映 / 担当 PR が別、を 1 件ずつ作業情報か進捗記録に残す
- PR を出す前のセルフレビューを飛ばさない: 機械で確かめられるもの（lint・リンク解決・
  発火の検証）→ review agent（観点は規範の欠落と実文の改変）→ 指摘を直す → PR
- レビューは PR ごとにゼロベースで行い、前の PR のレビュー結果を前提にしない
- レビュー指摘に対応するとき、その指摘を一般化して規範（core / 分類別 / claude-doc-authoring、
  種別別は rule / skill / agent / claude-md の各 authoring）へ取り込めるかを毎回検討する。
  取り込むなら同じ PR で、指摘箇所の修正とは別 commit にする

## 作業ブランチの注意

- PR ブランチと main で `rules/` の構成が違う。`rules/` は symlink で user global に
  配布されるため、checkout しているブランチで自分のセッションに載る規範が変わる
- ユーザーへの判断の確認は、決めなければならない判断を洗い出して 1 つのフォームにまとめる。
  1 件ずつ小分けに問わない
