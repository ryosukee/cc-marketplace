# html-communication の表現と機能紹介の保守

ギャラリーと共通実装の役割、および機能変更時の README と画像の更新を定める。

## ギャラリーと共通実装を分ける

- ギャラリーには、資料の内容に応じて作成側が任意に選ぶ、代表的な表現の見本を置く。
  採用条件と近縁表現との違いを添える。
- 採用済みの固定した操作は、生成元の書式・生成器・共通テンプレートへ組み込む。
  使うページのデータに応じて有効にし、ページごとに操作スクリプトを書かせない。
- 表現例が 1 つしかないことだけで置き場を決めない。
  作成側が選ぶ表現か、共通で提供する操作かで決める。
- 共通化が難しい場合は、困難な範囲、理由、追加で必要なデータや生成側の対応を示し、方式を利用者と決める。
  共通化できないという理由だけでギャラリーへ移さない。

why: 表現の見本と固定操作を混ぜると、作成側が毎回操作方式を選び、同じ操作をページごとに実装することになる。

## 機能紹介を実装と揃える

- 機能や UI を追加・変更・削除するときは、同じ変更で plugin README の該当説明と画像を更新する。
  既存の画像も変更の影響を受ける場合は撮り直す。
- README の画像は、機能紹介用の生成元から現行テンプレートで生成したページを実際のブラウザで撮影する。
  操作の前後を比較する必要がある機能は、両方の状態を載せる。
- 未実装の機能を利用可能として紹介しない。
  計画と検討中の試作は作業記録で扱う。
- 公開する代表画像と、明暗・狭幅の描画検証用画像を分ける。
  README 用の画像と再生成に必要な原文を plugin に保持し、検証だけの画像を混ぜない。

why: 操作の説明と画像が実装から遅れると、利用者が画面にない操作を探したり、古い挙動を期待したりする。
