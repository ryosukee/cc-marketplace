# plugin の eval を作る

ケースを作る順序と、ケースの中身の決め方を定める。ケースの書式・実行方法・子セッションの制約・
grader の種類・stub の記録の作りは [Plugin eval ハーネス](../../../evals/README.md) にある。

## ケースを作る順序

1. `plugins/{plugin}/evals/README.md` にケースの一覧を書く。ここで何を測るかを決める
2. 一覧を人に見せて合意を取る。ケースのファイルを書くのはその後
3. 一覧を、文脈を知らない subagent か別の CodingAgent にレビューさせ、指摘が無くなるまで直す
4. 一覧のとおりにケースを実装する。前準備は `evals/lib/seed.sh` のような共通の関数にまとめる
5. stub と前準備を手元で動かし、記録が一覧どおりの形で出ることを確かめる。
   grader の正規表現は、その記録に当ててから使う
6. 実装も同じようにレビューさせ、指摘が無くなるまで直す
7. 1 ケースを `--runs 1` で回し、load と grader が動くことを確かめる
8. 全件の実行の費用と時間を見積もって人に確認し、承認を得てから回す
9. 落ちたケースは、skill の問題か、ケースの作りの問題かを切り分けてから直す。
   手元で再現しない落ち方は、stub が子セッションで動いていないことを先に疑う。
   切り分けがつかないときは、落ちた実行の記録と再現の条件を人へ報告して止まる

## 一覧に書くこと

ケースごとに次の 4 つを書く。これが決まらないケースは、実装しても何も測れない。

- 依頼文の要点（何を頼むか）
- 期待（どの skill が発動するか / どの規則を守るか）
- 合格の条件（どの記録のどの形を見るか）
- 前準備で用意する fixture

動作の評価では、測る規則を SKILL.md から起こす。1 ケース 1 規則にする。

一覧を先に書くと、測る価値の無いケース（発動して当たり前の依頼、遠すぎる負例、
落ちようがない grader）が実装の前に見つかる。

## ケースの中身の決め方

### 依頼文のリーク

description の評価では skill 名もトリガー語も書かない。書くと発動して当たり前になり、
description を変えても結果が動かない。動作の評価では逆に skill を名指しする。発動を変数にしないため。

### 負例

トリガー条件に隣接する依頼だけを作る。無関係な依頼は、description を書き換えても
結果が動かないので情報にならない。

### 測らないもの

モデルの判断が入らない処理は測らない。スクリプトが必ず行うこと（label の付与など）は、
測っても skill の記述の良し悪しが分からない。

### fixture

測る規則が効く状況を実際に作る。直すべき箇所を指す指摘なら、その箇所を fixture の中に実在させる。
指摘だけ置いて対象が無いと、何もしなくても合格する経路ができる。

### 実行の枠

依頼の作業量に合わせて `max_turns` と `timeout_seconds` を決める。
打ち切られた実行は run error になり、スコアと判定を歪める。

### 満点が続くスイート

弁別できていない状態。間接的な正例と、隣接する負例を足す。

## レビュー工程

初回作成時とケース追加・変更時に、文脈を知らない subagent か別の CodingAgent のレビューを
回してから実行する。指摘ゼロになるまで修正と再レビューを繰り返す。

一覧と実装を別々に回す。一覧は何を測るかを、実装は記録と grader が測れているかを見る。
レビューは回すが、回しただけで通ったことにしない。stub は子セッションでだけ違う挙動をすることがあり、
文面を読むレビューではその差が出ない。

レビュー観点:

- プロンプトが skill のトリガー条件を代表しているか（実ユーザーの依頼として自然か）
- skill 名・トリガー語のリークが無いか
- grader の正誤（input_match の正規表現が対象 skill だけに一致するか、負例に min/max があるか）
- 負例の強度（境界事例が含まれるか、無関係な依頼だけになっていないか）
- 正例の難度分布（明示依頼だけに偏っていないか）
- fixture が依頼の前提を満たしているか（対象のファイル・カード・設定が揃っているか）
- 合格の条件ごとに、不合格になる経路を 1 つ挙げられるか
- stub の記録だけで判定できるか。判定に使う値が前準備の時点で確定しているか
