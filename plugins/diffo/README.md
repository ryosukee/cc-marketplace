# diffo

対応 CodingAgent: `Claude Code + Codex`

この plugin は、[Diffo 公式の `diffo` skill](https://github.com/DiffoHQ/diffo/blob/main/skills/diffo/SKILL.md)と併用し、次の機能を提供する。

- Diffo の実行前に ref-diffo の読み込みを確認し、未読なら読み込みへ誘導する hook
- CodingAgent のメイン会話を止めずに、バックグラウンドでポーリングを続けて Diffo のレビュー通知を受け取る仕組み
- レイヤー作成の依頼に、変更箇所への補足をインラインコメントで付ける指示を足す仕組み
- Diffo の Web UI の表示を変更し、機能を追加するパッチ

## 必要なものと導入

Diffo 公式 skill と CLI を使う場合は、以下が必要。

- Node.js 24 以上
- `npx`
    - Diffo CLI を `npx -y --prefer-online @diffohq/diffo@latest` で実行する
    - 各実行で npm registry の最新版を確認する
- `git`

Codex でレビュー通知を自動受信する場合は、上記に加えて以下が必要。

- Codex CLI
    - `codex queue` と `codex app-server daemon` を使用する
    - `codex queue --help` で対応状況を確認する
- Bash
- `shasum`
- `awk`

レイヤーの更新を依頼したときに、前回のインラインコメントを resolve させる場合は、以下も必要。

- `curl`
- `jq`

Diffo のブラウザ表示を変更する同梱スクリプト `bin/diffo-patch` を使う場合は、以下も必要。

- `npm`
- `node`
- `perl`
- `cmp`

公式 skill はこの plugin に同梱していない。利用する CodingAgent に別途導入する。

```bash
npx skills add DiffoHQ/diffo --skill diffo -g
```

plugin を導入するだけでは監視は始まらない。レビュー対象のリポジトリで
`npx -y --prefer-online @diffohq/diffo@latest --no-open` を実行する。
監視は[Claude Code で Diffo レビューを受ける](./claude-skills/ref-diffo/SKILL.md)または[Codex で Diffo レビューを受ける](./codex-skills/ref-diffo/SKILL.md)の手順で始める。

## 実行前に ref-diffo を読み込む

`PreToolUse` hook は、Diffo CLI と同梱スクリプトの実行を検出する。
そのセッションで ref-diffo を読み込んだ記録がなければ実行を拒否し、その環境用の SKILL.md の絶対パスを返す。
Claude Code では `Skill` ツールによる `diffo:ref-diffo` の発動、両 CodingAgent ではファイルの全文読み込みを受け付ける。
成功した読み込みを `PostToolUse` で確認した後、ref-diffo の手順に従って実行し直す。
hook は監視方法を指定せず、その手順を ref-diffo に集約する。

ファイルの読み込みは、ツールの対象パスと出力に SKILL.md の全文があることを確認する。
パスの言及、部分読み込み、読み込み要求を出しただけの状態では解除しない。
再開・コンパクションを含む `SessionStart` と、SKILL.md の本文変更で記録を無効にする。
`SessionEnd` で記録を削除する。

Codex では導入後に `/hooks` を開き、hook 定義を確認して信頼する必要がある。
plugin を有効にするだけでは hook は実行されない。
hook を無効にしている場合は `[features].hooks = true` に戻す。
設定と信頼の手順は [Codex Hooks](https://learn.chatgpt.com/docs/hooks) に従う。
Claude Code では plugin の hook を有効にする。hook を無効にした環境にはこの確認は適用されない。
入出力の仕様は [Claude Code Hooks](https://code.claude.com/docs/en/hooks) に従う。

検出対象は通常の `diffo`、`npx @diffohq/diffo`、`npm exec`、パッケージ内 CLI の `node` 実行、
同梱スクリプトとシェルのコマンド列・コマンド置換。
任意の別スクリプト内部や動的に組み立てたコマンドまで解析する仕組みではない。
読み込みの確認は、手順の内容をモデルが理解・遵守したことまでは保証しない。

## レイヤー作成の依頼にインライン補足を足す

Diffo の Layers タブでレイヤーの作成か更新を依頼すると、poll は `"kind":"layers"` の payload を返す。
Diffo の依頼文は、レイヤーの投稿以外にコメントを付けないよう求めている。
poll loop は payload を `bin/diffo-compact-payload.mjs` に通し、
依頼文のその文を [レイヤーを投稿するときのインライン補足](./references/layer-inline-comments.md) の本文に差し替える。
Diffo がその文を変えて見つからないときは、本文を依頼文の末尾に足す。
Codex の poller は、この依頼に限って、スレッドへの返信ではなくレイヤーの投稿を求める前置き文を付ける。

指示は poll の payload にだけ入る。チャットでレイヤーを頼んだときと、plugin の poll loop を通さずに
`diffo poll` を実行したときには届かない。

レイヤーの更新では、前回 agent が付けたインラインコメントを resolve してから付け直させる。
Diffo の CLI に resolve のコマンドは無いため、Diffo のブラウザ画面が使う HTTP API
（`GET /api/review` と `POST /api/review/threads/:id/state`）を `curl` で呼ばせる。
この API は Diffo の help に載っておらず、Diffo の更新で変わることがある。
resolve したスレッドは `diffo-patch` の既定の表示では隠れ、表示を切り替えると見られる。

## 未導入・異常終了時

監視が異常終了しても、Diffo のレビューと指摘は保持される。
原因を直して監視を再起動する。
plugin がなくても Diffo CLI の手動 `poll` と `reply` は使用できる。

## Markdown プレビューと表示の変更

`diffo-patch` を適用すると、次の 7 つの機能が追加・変更される。

- 解決済みスレッドを非表示にできる。表示・非表示を切り替えられ、初期状態は非表示。
  切り替えた状態はブラウザに保存され、スレッドの解決状態は変わらない。
- Markdown プレビューを GitHub 風に表示する。1 行の改行から余分な `<br>` を生成しない。
- 利用者は新規コメント・編集・返信の入力欄へファイルをドロップまたは貼り付けできる。
  plugin は添付のリンクを本文へ挿入する。
- 新規コメントと返信の下書きを、再描画後も同じブラウザタブ内で復元する。
- Finish review に LGTM ボタンを追加する。締めコメント欄の内容とともに、レビュー完了、
  `diffo end` と polling の終了、返信不要を伝える固定文を送信する。
- 行の中の変わった語を色付けする上限を、400 文字から 3,000 文字に上げる。
  Diffo は片方の行が上限を超えると語の差分を計算せず、行全体を変更として描く。日本語の段落は 1 行が長いので、400 文字では足りない。
  語の差分は 2 行の文字数の積に比例する表を作るので（3,000 文字どうしで約 36 MB）、上限は外さない。
- レビュー中にファイルを編集して行が増減しても、スレッドをコメントした行に描く。
  コメントした行を書き換えたときは、書き換えた後の行を推定して描く。
  スレッドをコメント時点と違う行に移したときと、コメントした行が見つからないときは、スレッドにバッジを付ける。

### plugin がスレッドに付けるバッジ

| バッジ | 付くとき | フォーカスで出る文 |
| --- | --- | --- |
| `thread relocated` | 行番号がずれ、コメントした行と一字一句同じ行を別の行番号で見つけた | コメント時点と今の行番号 |
| `thread relocated (guessed)` | コメントした行が書き換えられ、書き換えた後の行を推定した（行番号が変わらなくても付く） | コメント時点と今の行番号、推定したこと、コメントしたときの行 |
| `outdated` | コメントした行が今の差分に見つからず、ファイル単位の一覧に描いた | コメント時点の行番号、コメントしたときの行 |

※ 表 1 plugin がスレッドの見出しの行に付けるバッジ

理由の文は、バッジにマウスを載せたとき、キーボードでフォーカスしたとき、タップしたときに Diffo の tooltip（`data-tip`）で出る。
Diffo が自分で付けるバッジ（`code changed since this comment`、Draft などのスレッドの状態、GitHub から読み込んだスレッドの `outdated`）は、そのまま残る。

`thread relocated (guessed)` と `outdated` のスレッドでは、the commented change の欄に、コメントした時点の hunk 全体を出し、コメントした行に枠を付ける。
`thread relocated (guessed)` のスレッドは差分の行の下に描くので Diffo はこの欄を出さず、plugin が同じ見た目の欄を足す。
Resolved のスレッドは hunk を持たないので、コメントした行（範囲の先頭 10 diff 行まで）だけを出す。

スレッドの位置は、描くたびにスレッドの snapshot（`codeContext` と `anchored`）を今の差分の hunk の行と照合して決める。
同じ hunkId の hunk が書いたときと同じ行の並びで残っていれば、その中の位置を使う。
そうでなければ、コメントした側（old か new）の行の並びから、コメントした範囲のテキスト列が連続して一致する箇所を探す。
候補ごとに前後の行の一致数を数え、最大の候補が 1 つだけならそこに描く。
snapshot に前後の行があるのにどの候補も前後が一致しないときは、候補が 1 つでも次の段へ進む。

一字一句同じ行で決まらない new 側のスレッドは、base 側の行で位置を決める。base はレビュー中に変わらない。
snapshot の old 側の行（hunk の base の範囲）全体を、base のファイルで一字一句の連続一致で探し、1 か所に決まれば base の行番号が決まる。
snapshot をかたまり（context 行で区切った、連続する削除行と追加行）に分け、コメントした行を含むかたまりが置き換えていた base の行を求める。
今の差分でその base の行を置き換えているかたまりの追加行を候補にする。
書いたときと今の追加行の並びを一字一句同じ行で対応づけ、コメントした行が入るすき間の追加行に候補を絞る。
選ぶ行は、コメントした行から見てすき間の今の行のうちいちばん似ていて、その行から見てもすき間の書いたときの行のうちいちばん似ているのがコメントした行であるもの（互いにいちばん似ている組）に限る。
消した行や取り消した行のスレッドを、残った別の行の書き換えに付けないためである。
すき間の追加行の数が書いたときと同じで、同じ番目の行がこの組に入るなら、その行に描く（並んだときは位置で決める）。
そうでなければ、この組の行に描く。どちらも類似度（文字の最長共通部分列による）が 0.5 以上のときだけ描く。
ただし、すき間に書いたときの行も今の行も 1 行だけなら、同じ base の位置の 1 対 1 の置き換えなので、類似度を問わずその行に描く。
こうして決めたスレッドには `thread relocated (guessed)` のバッジを付ける。

この段で決まらないときは、さらに 2 段を順に試す。agent が節を書き直し、変更のかたまりの切れ目が変わった場合のためである。

1. snapshot の、コメントした行と同じかたまりのほかの追加行と一字一句同じ行が今の差分にあれば、その行を含む今のかたまりの中で、上と同じ方法で選ぶ。
   残っている行が 2 つ以上のかたまりに分かれていれば決めない。
2. 1 で決まらなければ、ファイルの今の追加行全体から、コメントした行に最も似た行を選ぶ。
   類似度が 0.5 以上で、2 番目に似た行を 0.1 以上上回り、その行から見ても書いたときのかたまりで最も似ているのがコメントした行であるときだけ描く。
   書いたときのほかの行と一字一句同じ行は候補にしない。

この 2 段で決めたスレッドにも `thread relocated (guessed)` のバッジを付ける。
2 段とも、base のファイルを取れて snapshot の位置が base で決まったときだけ使う。

base のファイルは、diffo のクライアントが `/api/review` と `/api/changeset` を取るときに `diffo-ui.js` が fetch に割り込み、
応答をクライアントに渡す前に `/api/file?side=base` で取っておく（行コメントのあるファイルだけ。changeset の更新では取り直す）。
そのため `diffo-patch` は、`diffo-ui.js` を Diffo の bundle より前に読み込ませる。

次のときは、どの段でも決まらず `outdated` として描く。

- base の行が 1 か所に決まらない、または base のファイルを取れなかった
- 変更を取り消した、またはコメントした行を消し、似た行も残っていない
- 似た行の類似度が足りないか、2 番目と差が無い
- コメントした行が hunk の外（畳まれた行）にしか無い
- 解決済みのスレッドで、書き換えられた（`codeContext` を持たないので base 側の段を使えない）
- 範囲が 10 diff 行を超える（snapshot が範囲の末尾を持たない）
保存されたアンカーとスレッドの状態は変えず、表示用のコピーだけを差し替える。
commit 別の表示、GitHub から取り込んだスレッド、snapshot の無い旧形式のスレッドは Diffo の既定のまま描く。
前後 3 行まで同じ内容の hunk がファイルに 2 つあり、コメントした方の変更を取り消すと、残った方に描かれる。
同じかたまりの短く似た 2 行のうち、コメントした行を消し、もう一方をコメントした行により似た文字列に書き換えると、
消した行のスレッドが書き換えた行に描かれる（例: `return a;` と `return ab;` から前者を消し、後者を `return a2;` にする）。
類似度でファイル全体から選ぶ段は、コメントした行を消し、別の場所に似た文の行を足したときも、その行に描く。
どれも内容からは区別できないため、対処しない。どの場合もバッジが付くので、フォーカスして元の行と比べられる。
このパッチは Diffo のクライアントの bundle に接続口を足すので（`bin/diffo-patch-placement.mjs`）、
配置処理の形が変わった版では当てずに止まり、Diffo の既定の位置に戻る。

## コメントへのファイル添付

利用者は新規コメント・編集・返信の入力欄へファイルをドロップまたは貼り付ける。
クリップボードに空でないテキストもある場合、plugin はテキストの貼り付けをそのまま通す。
その場合、plugin はファイルを添付しない。
plugin はドロップされたファイルと、テキストを伴わずに貼り付けられたファイルをサーバーへ送信する。
plugin は添付の絶対パスを Markdown のリンクとしてカーソル位置へ挿入する。
ファイル 1 件の上限は 20 MiB である。
入力欄の下には、送信中の表示または失敗の理由が出る。

plugin は PNG・JPEG・GIF・WebP の添付を入力欄の下にサムネイルで表示する。
plugin はそれ以外の添付をファイル名の札で表示する。
利用者が × を押すと、plugin は本文からその添付のリンクを消す。
利用者が本文のリンクを手で消した場合も、plugin は対応する表示を消す。
plugin は投稿後のコメントにも添付の表示を追加する。
利用者が画像を押すと、ブラウザは画像を新しいタブで開く。
サーバーは拡張子が PNG・JPEG・GIF・WebP 以外のファイルをダウンロードとして返す。

サーバーは添付を OS の一時ディレクトリの `diffo-attachments/<repo root の SHA-256 の先頭 12 文字>/` に保存する。
コメントの本文には、その保存先の絶対パスが残る。
agent は添付の絶対パスを開いて内容を読む。
利用者は添付の片付けを OS の一時ディレクトリの掃除に任せる。
本文からリンクを消しても、サーバーは保存済みファイルを削除しない。
OS が添付を削除すると、利用者と agent はその添付を開けなくなる。

サーバーへのパッチは、diffo を起動し直すまで効かない。
利用者は `diffo-patch` がサーバーへ新しくパッチを当てた場合、レビューしている repo で次のコマンドを順に実行する。

```bash
npx -y --prefer-online @diffohq/diffo@latest stop
npx -y --prefer-online @diffohq/diffo@latest --no-open
```

Diffo は停止前のレビューを保持する。
利用者は起動し直した後にブラウザをリロードする。
利用者は JS の変更が反映されない場合、ブラウザをハードリロードする。
上のコマンドが `@latest` を取り直すときに、diffo の新しい版が入る場合がある。
その場合、新しいパッケージにはパッチが当たっていない。
利用者は新しいパッケージに対して `diffo-patch` をもう一度実行する。
利用者は再適用でサーバーへ新しくパッチが当たった場合、上の停止と起動をもう一度行う。

## 更新・削除と状態

更新後は各 CodingAgent で plugin を更新し、新しいセッションで使う。
削除するときは各エージェントから plugin をアンインストールする。
Codex poller の排他 lock は `${XDG_STATE_HOME:-$HOME/.local/state}/diffo-codex-poll/` に置き、
正常終了時に削除する。レビューとスレッドのデータは Diffo 側が保持する。
`bin/diffo-codex-poll` の第 2 引数にレビュー名を渡すと、最初の poll でブラウザタブのタイトルを設定する。
読み込みの記録は CodingAgent が渡す plugin data の `ref-diffo-gate/` に置く。
plugin data が渡らない場合は `${XDG_STATE_HOME:-$HOME/.local/state}/diffo/ref-diffo-gate/` を使う。
記録は CodingAgent、session id、agent id と transcript のパスで分け、SKILL.md のハッシュだけを保存する。
`diffo-patch` は npx の Diffo パッケージを直接変更するため、Diffo 更新後は再適用する。
