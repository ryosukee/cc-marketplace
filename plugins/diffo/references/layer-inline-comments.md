# レイヤーを投稿するときのインライン補足

この依頼では、レイヤーを投稿した後に、変更箇所への補足をインラインコメントで付ける。
上の依頼文にある「Decisions:」の段落と「no reply, no comment」より、この指示を優先する。

## 概要とインラインに書く内容を分ける

- レイヤーの summary には、そのステップが何で、何を前提に読むかだけを書く
- 特定のファイルや行についての説明は summary に書かず、その行へのインラインコメントに書く。
  「summary のこの話は、具体的にはここ」という対応や、その箇所に固有の理由が対象

why: summary に `path:line` のリンクを並べると、レビュアーは差分とリンク先を行き来しないと読めない。
インラインコメントは、レビュアーが読んでいる差分の位置に表示される。

## decisions はインラインコメントへの案内にする

- decisions の各項目には、判断を 1 行で書いた `text` と、その判断を説明したインラインコメントの場所を示す `at` だけを書く。
  `detail` は書かない
- `at` には、インラインコメントで説明した範囲を `path:from-to` で書く。1 行だけなら `path:line` で書く
- 判断の理由と、選ばなかった案は、インラインコメントに書く
- インラインコメントで説明していない判断は、decisions に載せない

why: decisions はレイヤーのカードに表示され、`at` を押すと差分のその位置へ移る。
説明をインラインコメントだけに書けば、同じ判断の説明が 2 か所に分かれない。

## コメントを付ける箇所

- summary と差分を読めば分かる変更には付けない
- summary で述べた話の、具体的な対応箇所に付ける
- 設計判断の理由がある箇所に付ける
- 複数の箇所の変更が依存しあうときは、コメントの中で互いの `path:line` を書いて参照する
- `"kind":"mechanical"` のレイヤーのファイルには付けない

## 付け方

- `npx -y --prefer-online @diffohq/diffo@latest comment <file> --line <n>` で付ける。長い本文は stdin で渡す
- `--line` には差分の新しい側に表示されている行（追加行か、hunk の中の文脈行）を指定する。
  差分に無い行を指定すると、ファイル単位のコメントに変わる
- 関数や設定ブロックのように複数行にまたがるまとまりに付けるときは、まとまりの最終行を `--line` に指定し、
  本文の冒頭に範囲を `L10-25` の形で書く。
  最終行が削除行のときは、そのまとまりのうち差分の新しい側に表示されている最後の行を指定する
- ファイルの新規作成・削除・リネームへの補足と、削除行への補足は、`--line` を付けずにファイルへのコメントにする

why: Diffo はレビュアーの範囲コメントを範囲の最終行の下に表示する。
agent のコメントも最終行に付けると同じ位置に並ぶ。画面のラベルには指定した 1 行しか出ないため、範囲は本文で示す。

## PR レビューのとき

- 設計判断の理由は、PR の説明か commit に書いてあるものだけを書く。書いていない理由を推測で書かない
- `--pr-comment` は付けない

why: PR レビューの agent はそのコードを書いていない。
`--pr-comment` を付けたコメントは、作成者宛ての PR コメントの下書きとして扱われる。

## refresh のとき

レイヤーを投稿し直す前に、前回のインラインコメントを次のコマンドで resolve する。
resolve するのは、agent の発言だけでできた、行またはファイルに付いたスレッドだけにする。
それ以外のスレッドは resolve しない。

```bash
url=$(npx -y --prefer-online @diffohq/diffo@latest status --json | jq -r .url)
curl -s "$url/api/review" \
  | jq -r '.threads[]
      | select(.state != "resolved" and .anchor.kind != "changeset"
               and all(.messages[]; .author == "agent"))
      | .id' \
  | while read -r id; do
      curl -s -X POST -H 'Content-Type: application/json' \
        -d '{"state":"resolved"}' "$url/api/review/threads/$id/state"
    done
```

resolve した後に、インラインコメントを全部付け直す。

why: refresh ではレイヤーがまるごと置き換わる。前回のコメントを残したまま付け直すと、同じ箇所に新旧のコメントが並ぶ。
resolve したスレッドは画面から隠れ、レビュアーは表示を切り替えれば見返せる。

## 順序

1. refresh なら、前回のインラインコメントを resolve する
2. レイヤーを投稿する
3. レイヤーの順に、インラインコメントを投稿する
4. poll を再開する
