# Diffo の表示調整

この plugin は、Diffo のブラウザ画面の表示を変更するスクリプト `bin/diffo-patch` を同梱する。
適用すると、次の 7 つの機能が追加・変更される。

- 解決済みスレッドを非表示にできる。表示・非表示を切り替えられ、初期状態は非表示。
  切り替えた状態はブラウザに保存され、スレッドの解決状態は変わらない。
- Markdown プレビューを GitHub 風に表示する。1 行の改行から余分な `<br>` を生成しない。
- 利用者は新規コメント・編集・返信の入力欄へファイルをドロップまたは貼り付けできる。
  plugin は添付のリンクを本文へ挿入する。
- 新規コメントと返信の下書きを、再描画後も同じブラウザタブ内で復元する。
- Finish review に LGTM ボタンを追加する。締めコメント欄の内容とともに、レビュー完了、
  `diffo end` と polling の終了、返信不要を伝える固定文を送信する。
- 行の中の変わった語を色付けする上限を、400 文字から 3,000 文字に上げる。
- レビュー中にファイルを編集して行が増減しても、スレッドをコメントした行に描く。
  描くたびに、保存された行番号ではなく、書いたときの行の内容で今の差分の行を探し直す。
  コメント時点と違う行に描いたスレッドには `thread relocated` のバッジを付ける。
  コメントした行が書き換えられ、書き換えた後の行を推定したときは `thread relocated (guessed)` にする。
  見つからないスレッドは別の行に付けず、ファイル単位の一覧に `outdated` のバッジを付けて描く。
  移した理由は、バッジにフォーカスすると出る。推定したスレッドと見つからないスレッドでは、
  the commented change の欄にコメントした時点の hunk を出し、コメントした行に枠を付ける。
  保存されたスレッドの位置と状態は変えない。

Diffo 公式 skill の command を
`npx -y --prefer-online @diffohq/diffo@latest --no-open` に置き換えて起動した後に、
この plugin の `bin/diffo-patch` を実行する。
plugin root は、読み込んだ SKILL.md のパスから 2 階層上にある。

```bash
"<plugin root>/bin/diffo-patch"
```

> [!NOTE]
> diffo の起動後に適用する。npx が diffo を更新した後は再適用する。
> 適用後はブラウザをリロードする。変更が反映されなければハードリロードする。
> 表示切替が出ないときは、Diffo 側の class 名や `aria-label` の変更を確認する。
> 「placement: 当てる先が 1 か所に決まらない」で止まったときは、Diffo の更新でスレッドの配置処理が変わっている。
> 他のパッチは当たっているが、スレッドの位置は Diffo の既定のまま（保存された行番号の行）に描かれる。

`diffo-patch` 適用後は、返信の段落間に空行を入れる。段落内で強制改行するときだけ
`<br>` を使い、改行のつもりで文字列 `\n` を渡さない。

## コメントへのファイル添付

利用者は新規コメント・編集・返信の入力欄へファイルをドロップまたは貼り付ける。
クリップボードに空でないテキストもある場合、plugin はテキストの貼り付けをそのまま通す。
その場合、plugin はファイルを添付しない。
plugin はドロップされたファイルと、テキストを伴わずに貼り付けられたファイルをサーバーへ送信する。
plugin は添付の絶対パスを Markdown のリンクとしてカーソル位置へ挿入する。
ファイル 1 件の上限は 20 MiB である。
入力欄の下には、送信中の表示または失敗の理由が出る。

plugin は PNG・JPEG・GIF・WebP の添付を入力欄の下にサムネイルで表示する。
plugin はそれ以外の添付をファイル名の札で表示する。
利用者が × を押すと、plugin は本文からその添付のリンクを消す。
利用者が本文のリンクを手で消した場合も、plugin は対応する表示を消す。
plugin は投稿後のコメントにも添付の表示を追加する。
利用者が画像を押すと、ブラウザは画像を新しいタブで開く。
サーバーは拡張子が PNG・JPEG・GIF・WebP 以外のファイルをダウンロードとして返す。

サーバーは添付を OS の一時ディレクトリの `diffo-attachments/<repo root の SHA-256 の先頭 12 文字>/` に保存する。
コメントの本文には、その保存先の絶対パスが残る。
agent は添付の絶対パスを開いて内容を読む。
利用者は添付の片付けを OS の一時ディレクトリの掃除に任せる。
本文からリンクを消しても、サーバーは保存済みファイルを削除しない。
OS が添付を削除すると、利用者と agent はその添付を開けなくなる。

サーバーへのパッチは、diffo を起動し直すまで効かない。
利用者は `diffo-patch` がサーバーへ新しくパッチを当てた場合、レビューしている repo で次のコマンドを順に実行する。

```bash
npx -y --prefer-online @diffohq/diffo@latest stop
npx -y --prefer-online @diffohq/diffo@latest --no-open
```

Diffo は停止前のレビューを保持する。
利用者は起動し直した後にブラウザをリロードする。
利用者は JS の変更が反映されない場合、ブラウザをハードリロードする。
上のコマンドが `@latest` を取り直すときに、diffo の新しい版が入る場合がある。
その場合、新しいパッケージにはパッチが当たっていない。
利用者は新しいパッケージに対して `diffo-patch` をもう一度実行する。
利用者は再適用でサーバーへ新しくパッチが当たった場合、上の停止と起動をもう一度行う。
