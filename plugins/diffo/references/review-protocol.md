# Diffo レビューの共通手順

Diffo 公式の `diffo` skill と CLI の `help agent` にある基本プロトコルに加え、
payload を読んで返信するときに使う補足規範。

## 返信先は各スレッドの id から取る

縮約済み通知では各 `threads[].id`、元の payload では各 `### Thread N` 見出しの直下にある
`id:` 行を返信先とする。`threadIds` の配列とスレッドの並び順だけでは対応づけない。

why: 配列の並びと本文の並びは一致する保証が無い。ずれたまま返信すると、
別のスレッドへ回答が付き、指摘した側は自分の指摘が無視されたと読む。

## 指定された文言はそのまま当てる

レビュアーが置き換え後の文言を書いて寄こしたときは、その文言をそのまま使う。
言い換えない。表記の揺れ（全角の数字など）だけは、その文書の既定に合わせて直す。

why: 文言を指定する指摘は、意図が既に文言の形で確定している。
言い換えると、指摘した側は同じ指摘をもう一度書くことになる。

## 説明を足す前に、情報が増えるかを見る

指摘に応えるとき、結論の言い換えや「確認すべき項目が残っている」という趣旨の文を足さない。
確認すべき項目があるなら、その項目の中身を書く。

判定基準: 足した文を消したとき、読み手が知ることは減るか。減らないなら足さない。

## 承認だけの締めには返信しない

レビュアーの締めのスレッドが LGTM・approve・「merge して OK」のような承認だけなら、そのスレッドへ返信しない。
`diffo end` でレビューを閉じ、以降の報告（push・merge の実行結果）はターミナルで行う。
締めに質問や指示が含まれるときだけ、その部分に返信してから閉じる。

why: 承認だけの締めに返信しても、レビュアーが知ることは増えない。レビューは終わっており、報告の場はターミナルに戻っている。

## ターミナルには情報を足さない

diffo でレビューを受けている間、ターミナルに書くのは「対応して回答した」ことと閲覧先の URL だけにする。
回答の中身、確かめたこと、残った論点、ユーザーへの質問をターミナルに書かない。
質問や新しい論点は、該当スレッドへの返信か `diffo comment` で diffo に出す。

why: レビュー中のユーザーは diffo を見ていて、ターミナルを見ていない。

判定基準: ターミナルに書こうとしている文から、「対応して回答した」と URL を除いて何か残るか。残るなら diffo に出す。
