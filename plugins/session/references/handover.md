# 引き継ぎ資料確定の手順

このセッションで引き継ぐべき作業、合意、成果物、現在の状態と参照先を過不足なく記録する。
会話にしか残っていない決定も含め、次セッションが同じ前提で作業を続けられる handover に確定する。

## 1. draft を特定して補完する

`handover-init.md` と `draft-tasks.md` を読み、`.handover/` と対象 draft を
特定する。draft がなければ会話から必要な情報を集め、`handover-template.md` に
「セッション内タスク」を加えて作る。会話、draft、成果物、参照した資料を突き合わせ、
次セッションに必要な背景、ユーザーが決めたゴール・原則、決定事項、現在の状態、
未完了の作業、再開手順を補う。

- 会話中だけで合意した決定は、結論とその判断に必要な理由を「決定事項」に書く。
  別の資料に記録済みなら、次セッションでもその資料が残り、同じ内容を確認できるか
  確かめる。確認できる資料は内容を複製せず、パス・該当箇所・到達点を書く。
  セッション限りの scratchpad など、消失・更新され得る資料だけにある情報は、
  参照だけにせず、引き継ぐ内容を handover に書く。
- 「後でやる」「今回はやらない」とされた作業は、優先度を問わず棚卸しの対象にする。
- 「ここに書いてある」と引き継ぐ資料は、その所在と次に読むべき箇所を明記する。

必要のない節を無理に埋めず、ファイルパス、ブランチ名、コミット ID などの識別子は省略しない。

## 2. セッション内タスクを棚卸しする

draft の「セッション内タスク」を会話、成果物、作業状態、プロジェクトの
管理記録と突き合わせ、追加・完了・中止の書き漏れを補う。

- 次セッションで必要な作業は、粒度・優先度にかかわらず「復元タスク」に全件書く。
- 完了した作業は成果物とともに「完了したこと」に書く。
- やらないと決めた作業は復元タスクに含めない。次セッションで再提案しそうな
  決定だけ、「却下と決めたこと」に決めた内容と時点を記録する。
- 作業の制約はタスクの description か設計文書、恒常的な運用の約束は
  「ゴール・原則」に置く。事故・失敗は retrospective の対象であり、
  明文化しないなら handover に残さない。

分類をユーザーに確認する。draft の slug をセッション内容に合わせて確定し、
分類結果を反映する。確定形から draft 専用の「セッション内タスク」を削除する。

## 3. 機械検査を実行する

plugin の `scripts/check-handover.mjs` を `node` で実行する。
`node` または `git` がなければ不足を報告し、検証済みと扱わない。
実行できた場合は JSON 出力の `total` が 0 になるまで直して再実行する。
終了コードは 0 が指摘なし、1 が指摘あり、2 が前提条件エラー。

出力の `git` は branch、HEAD、未コミット件数、stash 件数、upstream との
ahead-behind、worktree 数の実測値であり、検査の合否ではない。
本文の「現在の作業状態」と自分で突き合わせ、違えば修正する。
将来作る予定のパスを記した場合は「（新設予定）」と明記する。

## 4. 意味レビューを実行する

機械検査が通った後、`handover-review.md` に従って独立した子 agent に
**一度だけ** read-only の意味レビューを依頼する。渡すものは、対象 handover の
絶対パス、機械検査の JSON、今回触れた decision-record・設計文書の所在、
`handover-review.md` の絶対パス。CodingAgent 別の入口に agent の呼び出し方があれば
それに従う。子 agent が使えない場合は省略を報告し、独立レビュー済みと書かない。
レビュー中は対象ファイルを編集しない。

指摘 0 件を目標に反復しない。次セッションの行動が変わる指摘は修正し、
**追加のレビューを一度だけ**行う。文言・構造だけの指摘は修正して終了する。
識別子と git 状態の照合は機械検査が担当し、意味レビューへ重複して頼まない。

## 5. 確定する

検査とレビューの結果を確認した draft を `.handover/todo/` へ移す。
ユーザーに handover の絶対パスと、次回の start skill の使い方を伝える。
handover は commit せず working tree に残す。
