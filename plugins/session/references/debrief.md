# セッション棚卸しの手順

終了前に実際の作業状態と会話を突き合わせ、draft に記録する。

1. 作業した各リポジトリでブランチ、未コミット変更、worktree、stash、
   本セッションのコミットを確認する。`git branch --show-current`、
   `git status -s`、`git worktree list`、`git stash list`、`git log --oneline`
   を使い、他に触れたリポジトリでも状態を確認する。
   main 上の未コミット変更、残存 stash、宙に浮いた worktree などは警告として記録する。
2. 会話から完了した成果物（PR 番号・コミット ID・変更ファイル）、設計判断、
   外部サービスへの変更を抽出する。確認していない状態を完了と推測しない。
3. プロジェクトの指示・README・設定から、そのプロジェクトで使うタスク管理を確認し、
   実態との食い違いを棚卸しする。方式は決め打ちしない。特定できなければ省く。
4. `handover-init.md` と `draft-tasks.md` を読み、`.handover/` と対象 draft を特定する。
   draft がなければ `handover-template.md` に「セッション内タスク」を加えて作る。
   会話・成果物・作業状態と draft の表を突き合わせ、次の書き漏れや状態の変化を補う。
   - 着手しなかった予定と、要求されたが完了していない作業
   - 議論で出たが実行していない改善案
   - 方針変更で中止した作業

   「やらない」と決めたものは決着済みで、未完了に含めない。
   「今回はやらない」と決めたものだけを未完了として残す。
5. draft の「背景」「ゴール・原則」「決定事項」「現在地と再開手順」
   「完了したこと」「現在の作業状態」「参照すべき資料」「セッション内タスク」を更新する。
   会話にしか残っていない合意を落とさず、記録済みの内容は所在と到達点を記す。
   参照資料には実際に参照・作成した文書や外部 URL を記録する。
   次セッションへ何を残すかは handover で決める。
6. 棚卸し結果の要点をユーザーに伝え、警告があれば対応要否を確認する。
