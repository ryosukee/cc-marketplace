# セッション中の作業タスク

セッション中の作業タスクの SoT は、作業対象の `.handover/draft/` にある現在の draft とする。
CodingAgent の会話や機能に残る作業状態は、draft と照合する材料に留める。

## draft の構造

`handover-template.md` の見出しに加え、draft にだけ `## セッション内タスク` を置く。
作業タスクは次の表で管理する。タスクがなければ見出しの下に `なし` と書き、
最初の作業が決まったときに表へ置き換える。
draft の「復元タスク」には作業を重複記載せず、確定前は `なし` とする。

| subject | description | 状態 |
| --- | --- | --- |
| {作業名} | {対象と完了条件} | 未着手 |

状態は `未着手`、`進行中`、`完了`、`却下` のいずれかにする。
同じ作業を別の行へ重複させず、進捗が変わったら既存行を更新する。

## セッション中の更新

- draft がない場合は `handover-init.md` に従って保存先を決め、
  `handover-template.md` の見出しと「セッション内タスク」を使って作る。
- 開始時に、前回の「復元タスク」を全件 draft に写す。
  今回着手しない作業も `未着手` のまま残し、終了時に改めて行き先を決める。
- 新しい作業を引き受けた時点で draft に追記する。作業が完了・中止したら状態を更新する。
- 別のリポジトリで行う作業も、このセッションで引き受けたなら対象リポジトリを description に書く。
- draft のパスが分からなくなったら、`handover-init.md` に従って探す。

## 終了時の棚卸し

draft の表だけで判断せず、会話、成果物、作業状態、プロジェクトの管理記録と突き合わせる。
書き漏れた作業を補い、状態を確定する。

- 完了した作業は「完了したこと」に成果物とともに記録する。
- 次セッションで行う作業は、状態や元の優先度にかかわらず「復元タスク」に移す。
- 次セッションで行う作業がなければ「復元タスク」の本文を `なし` の 1 行にする。
- やらないと決め、次セッションで再提案されうる作業は「却下と決めたこと」に記録する。
- 次セッションへ渡す handover から「セッション内タスク」を削除する。

最終的な handover の「復元タスク」は次セッションで必要な作業だけを示す。
セッション内で完了した作業や、やらないと決めた作業を混ぜない。
