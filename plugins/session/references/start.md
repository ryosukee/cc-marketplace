# セッション開始の手順

前回の引き継ぎ資料を読み、ユーザーが今回の作業を選べる状態にする。

1. `handover-init.md` と `draft-tasks.md` を読む。`handover-init.md` に従って
   `.handover/` を特定・初期化し、その絶対パスを以降の操作に使う。
2. `todo/` の引き継ぎ資料を全件読む。資料がない場合も draft の作成へ進む。
3. 資料があれば統合し、次の情報だけをユーザーに提示する。
   - 何をしている途中か（1〜2 文）
   - どこまで終わったか（PR 番号・コミット ID などの成果物識別子）
   - 再開時に最初に行う作業（読むファイルや実行するコマンド）
   - 復元タスクの全件

   handover の節を順に要約しない。今回進める復元タスクと、前回の続きを行うか
   別の作業にするかはユーザーに判断を委ねる。
4. `handover-init.md` に従って既存 draft を確認する。あれば内容を示し、
   再利用するか新しい draft に置き換えるかユーザーに確認する。
   新しく作る場合は既存 draft と重ならない仮の slug を選んで `draft/` に作り、
   `handover-template.md` の骨格に `draft-tasks.md` の「セッション内タスク」を加える。
   前回の引き継ぎ資料から、次セッションにも必要な背景・原則・決定事項・
   却下した選択肢・成果物・現在の作業状態・再開手順・参照先を該当節へ記録する。
   復元タスクも全件記録し、今回着手しない作業は `未着手` のまま残す。
   今回選んだ新しい作業があれば追記する。
   既存 draft を置き換える場合も、各節で引き継ぐべき情報とセッション内タスク全件を
   新しい draft に移す。新しい draft の保存と内容の確認後に
   旧 draft を削除し、`draft/` に 1 ファイルだけ残す。
5. draft を保存してから、読み終えた `todo/` の引き継ぎ資料を `archive/` へ移す。
   引き継ぎ資料でないファイルは移さず、置き場の修正を提案する。
   移したファイル名と draft に記録した作業を報告する。
6. draft に記録した作業から、次に着手するものを一つ提案する。
   作業が未定ならユーザーに尋ね、決まった時点で draft に追記する。
   テキストで伝え、ユーザーが自由に返答できるようにする。

開始後に作業が増えたり進捗が変わったりしたら、`draft-tasks.md` に従って
その時点で同じ draft を更新する。終了時の棚卸しまで記録を先送りしない。
