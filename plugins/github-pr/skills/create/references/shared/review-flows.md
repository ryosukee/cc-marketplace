# PR のレビューの 2 系統

PR を draft で作った後の流れは、誰がレビューするかで 2 つに分かれる。open（ready for review）とマージを誰が行うかが違う。

## 系統 A: セルフレビュー・セルフマージ

レビュアーが作者本人だけの repo。

1. draft で作る
2. 作成直後に open する（`gh pr ready {number}`）。open は形式的な操作なので指示を待たない
3. 本人がレビューし、approve か comment を付ける
4. approve が付き、本人からマージの指示を受けたらマージする

## 系統 B: 他人にレビューしてもらう repo

作者本人のほかにレビュアーがいる repo（組織の repo など）。

1. draft で作る
2. 本人が draft のままレビューし、その指摘に対応する
3. open は本人の確認が済んだ合図として本人が行う。open は他人にレビューを依頼する公開の操作なので、指示なしに行わない（本人の指示があれば代わりに行う）
4. 他人がレビューし、approve を付ける
5. マージは人間が行う。Claude はマージしない

## 判定

repo の所有者が本人のアカウント（組織ではない）で、他のレビュアーがいなければ A。組織の repo か、他のレビュアーがいれば B。迷ったら B。

## approve とチャットの了承

どちらの系統でも、マージの前提は PR に approve のレビューが付いていること。チャットで「マージしてよい」と言われても、approve が無ければマージの前提を満たさない。会話の表現（「そろそろマージできる」等）は、まだマージできない状態を含む。approve は GitHub 上の状態なので判定が一意になる。
