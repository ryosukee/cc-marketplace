# 状態とイベントの操作図

状態の切り替わりと、その操作に伴う通信を試せる図の生成元を定める。
ページを作るときに `stateMachine` ブロックを使う。

## 使う場面と保持する値

単一の現在状態を持ち、イベントの結果によって次の状態が決まる対象に使う。
成功・失敗の分岐は別の遷移として定義し、再試行は同じ状態へ戻る遷移として定義する。
階層状態や同時に有効な複数の状態軸は、このブロックでは実行しない。
その関係を説明する静的な図には [図の書式](./figure-format.md) を使う。

操作中は、作成時の初期状態、読者が選んだ開始状態、現在の状態を別々に保持する。
ノードを選ぶと開始状態と現在状態をそのノードに変え、履歴を空にする。
「初期状態に戻す」は作成時の初期状態から始め直す。
終端状態は、その状態を `from` に持つ遷移が無いことで表す。

通信と操作の履歴は図の試行用であり、フォームの回答には含まれない。
再読込すると試行は初期状態に戻る。外部通信や業務処理は実行しない。

## ブロックと全体の項目

`{ "stateMachine": { ... } }` を本文のブロックに置く。
[動作例の生成元](../../../docs/features/demo-r003.json) を、座標を含む例として使える。
図の HTML・JavaScript をページ固有の figures ファイルへ写さない。
共通の描画処理と操作処理を使うことで、入力・アクセシビリティ・回答との分離が揃う。

全体の項目はすべて必須。未対応の項目は検査で拒否する。
`id` から作る図本体・矢印・説明の DOM id もページ内で一意にする。
たとえば `sample` と `sample-arrow`、`sample` と `sample-desc` の組合せは使えない。
文字列はプレーンテキストとして扱い、インライン記法や HTML は解釈しない。

| 項目 | 値 |
| --- | --- |
| `id` | ページ内で一意の識別子。英小文字で始まる英小文字・数字・ハイフン |
| `title` | 空でない図の名前。図全体のアクセシブル名 |
| `initial` | 作成時の初期状態の node id |
| `description` | 状態の関係を説明する空でない代替テキスト |
| `legend` | 青枠や結果の分岐など、図法の意味を説明する空でない文字列 |
| `width`, `height` | SVG の幅と高さ。1〜4000 の数値 |
| `nodes` | 空でない状態の配列 |
| `transitions` | 空でない遷移の配列 |
| `participants` | 空でない通信参加者の配列。左から並べる順 |
| `paths` | 遷移の線の配列。線を持たない場合は空配列 |
| `decorations` | 結果分岐の菱形やイベント名の配列。不要なら空配列 |

## 状態・遷移・通信

状態には `id`, `label`, `description`, `x`, `y`, `width`, `height` を書く。
`id` の書式は全体の id と同じで、nodes 内で一意にする。
`label` と `description` は空でない文字列。
座標は非負、幅は 100 以上、高さは 64 以上の数値にし、図の寸法内へ収める。
ノード名、説明、「ここから試す」の領域を保持できる寸法を取る。

遷移には次を指定する。

| 項目 | 値 |
| --- | --- |
| `id` | transitions 内で一意の識別子。node id と同じ書式 |
| `from`, `to` | 既存の node id。自己ループは同じ id |
| `event` | 履歴と操作のアクセシブル名に出すイベント名 |
| `result` | 図に置く操作ボタンのラベル。成功・失敗など結果を含める |
| `x`, `y`, `width`, `height` | 操作ボタンの領域。座標は非負、寸法は正の数値。図の寸法内へ収める |
| `messages` | 通信順の配列。対外通信が無い場合は空配列 |
| `local` | 任意。通信を伴わない内部処理など、履歴に残す空でない説明 |

`event` と `result` は空でない文字列。
同じイベントの成功と失敗は、別々の `id`, `result`, `to`, `messages` を持つ遷移にする。
現在状態から出る遷移だけが実行できるため、無効なイベントを別の状態から試すことはできない。

参加者には一意な `id` と空でない `label` を書く。
メッセージには `from`, `to`, `label` だけを書く。
`from` と `to` は既存の participant id、`label` は空でない文字列。
同じ参加者へのメッセージは自己通信として表示する。
履歴は開始状態から現在状態まで連続して残り、状態が変わらない再試行も 1 回として数える。

## 線と結果分岐の座標

`paths` の各要素には `d`, `transitions`, 任意の `arrow` を書く。
`d` は SVG path の座標文字列。path 命令と数値・空白・コンマだけを受け付ける。
`transitions` は、この線を通る既存の transition id の空でない配列。
成功・失敗に共通する分岐前の線には両方の id を入れる。
`arrow: true` は矢印を付ける。省略時は矢印を付けない。
実行できる線は青、直前の遷移が通った線は破線で示す。

`decorations` の各要素は、`{ "d": "M…Z" }` または `{ "text": "イベント名", "x": 100, "y": 100 }` とする。
`d` は菱形などの分岐記号の path 座標。`text` は中央揃えのラベルで、数値の `x`, `y` を必須とする。
分岐記号は状態として選択できない。結果判断を永続する業務状態と誤認させないため、ノードに混ぜない。

図の座標は自動配置しない。状態の個数や往復・自己ループの関係に合わせて、線とラベルの重なりを調整する。
横並びは状態図と履歴、縦並びは状態図の下に履歴を置く。
狭い幅では図内で横スクロールし、ノードや文字の寸法を縮めない。

## 静止表示と検証

JavaScript が無効でも、状態図と全遷移・全通信の一覧を読める。
印刷時は操作バーを隠し、全遷移の一覧と試行済みの履歴を表示する。
OS の reduced motion 指定があるときは現在状態の強調アニメーションを止める。

生成前に id の重複、状態・参加者・線の参照、座標、未対応の項目を検査する。
生成した HTML は通常のページ検査に加え、明暗・狭幅・横並びと縦並びで描画確認する。
成功、失敗、自己ループ、終端、開始状態の変更、初期状態への復帰を、それぞれ実際に操作して確かめる。
フォームでは操作後も回答の preview に試行履歴が混ざらないことを確かめる。
宣言が妥当でも線やラベルの配置が読み取れるとは限らないため、座標の検査だけで完了にしない。
