# revision diff

現行の文と改訂後の実文を並べ、削る箇所と足す箇所を面と字面の両方で示す。

## 使ってよい条件

- 文書・規範・設定の改訂案を提示し、どこが変わるかを読ませたいとき
- 現行と改訂後の両方を見せる必要があるとき
- 変更が文の一部で、全文の書き換えではないとき

## 使ってはいけない条件

- 全文を書き換えるとき。差分の面だらけになって読めない
- 変更点が構造（節の並び替え、削除）のとき。面では表せない

## 近縁パターンとの区別

現行の文は引用（`blockquote`）、改訂後の実文はこのパターンの `.after` に入れる。
改訂後は引用ではないので引用ブロックを使わない。

## 色について

削除の赤面と追加の緑面を使う。雛形の既定の 3 役割の外側だが、
GitHub 以来この配色に意味が定着しており、読み手が別の意味に取る余地が小さい。

色だけに載せない。削除には取り消し線を併記する（WCAG 1.4.1）。
色はこのパターンの中で閉じ、本文の地の文へ持ち出さない。
