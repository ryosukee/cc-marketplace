# フローチャート：処理順と条件判断

入力検証から条件判断を経て登録または修正案内へ進む処理順を示す。

## 名前

フローチャートは公式の呼称。ディレクトリ名は条件判断を持つ見本を区別するために付けた。

## 使ってよい条件

- 処理を実行する順序と、判断結果による経路の違いを説明するとき
- 矩形を処理、菱形を判断として読み分けられるとき

## 使ってはいけない条件

- 保持される業務状態と、イベントによる変化を説明するとき。その場合は状態図を使う

## 近縁パターンとの区別

state-result-branch は予約済み・通知済みなどの状態をノードに置く。この例は入力検証・登録などの処理をノードに置く。
