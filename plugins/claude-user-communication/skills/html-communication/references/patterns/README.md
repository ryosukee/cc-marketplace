# 見せ方のパターン集

雛形が持たない一点物の見せ方を、名前を付けて貯める。
議題ごとに作った表現のうち、次に使えるものだけを残す。

このファイルはカタログ自体の規約だけを持つ。個々のパターンは同階層のディレクトリにある。

## 置き場の役割

| 置き場 | 役割 |
| --- | --- |
| [入り組んだ説明・報告・確認は HTML で行う](../../SKILL.md) | 守るべき規定。色の役割、フォントの段、表の作り、設問の置き方 |
| `templates/page.html` | 基盤の実装。全ページが使う CSS と HTML |
| このディレクトリ | 個別のパターン。使うページだけが取り込む |

パターンの CSS を雛形へ入れない。入れると使わないページも運ぶことになり、
雛形が伸び続ける。パターンは独立したディレクトリに置き、使うページへ貼り込む。

## ディレクトリの構成

パターン 1 つにつきディレクトリ 1 つ。中身は 3 ファイルに固定する。

```text
patterns/
├── README.md                       # このファイル
└── {pattern-name}/
    ├── README.md                   # 名前・条件・出典
    ├── style.css                   # CSS。雛形の CSS トークンを参照してよい
    └── example.html                # 使用例の HTML 断片
```

`{pattern-name}` は英小文字とハイフンにする。公式のデザインシステムに同じ形があれば
その呼称に揃え、無ければ説明的な名前を付ける。

## パターンの README に書くこと

5 つだけ。増やさない。

- 名前。公式の呼称に揃えたか、自分で付けたかを書く。自分で付けたなら公式に無い旨も書く
- 何を表すか。1 文
- 使ってよい条件
- 使ってはいけない条件
- 近縁パターンとの区別。似ているが別物のものがあれば、使い分けの基準

出典があれば情報源ブロックで最後に置く。

判定基準: 次にこの形を使いたくなったとき、条件だけ読んで採否を決められるか。
決められないなら条件の書き方が悪い。

## 使い方

1. このディレクトリを見て、使えるパターンがあるかを確かめる
2. あれば `style.css` を生成ページの `style` 要素の末尾へ入れ、`example.html` を参考に本文を書く
3. 無ければその場で作る。次に使えるものだけ、作った後にここへ足す

生成ページは self-contained が必須なので、CSS は必ずページの中へ貼り込む。
外部ファイルとして参照しない。

## 実物を並べて見る

全パターンを 1 枚に並べた HTML を作れる。

```sh
node "${CLAUDE_PLUGIN_ROOT}/skills/html-communication/scripts/build-gallery.mjs" <出力先パス>
```

雛形の基盤 CSS と全パターンの `style.css` を連結し、各パターンの `example.html` を
並べて出力する。共通ページディレクトリへ `gallery.html` として出すと、
index の「見せ方のパターン集」からリンクで辿れる。
一覧のエントリは持たせない（回答・確認の対象ではないため）。

**このディレクトリを更新したら gallery を作り直す。** パターンの追加・削除・修正の
どれでも作り直す。生成物は手で編集しない。

### gallery が雛形のページレイアウトを引き継がない理由

生成物の本文は `main` ではなく `.gallery` で包む。雛形の CSS は `main` を
3 pane のグリッドにするメディアクエリを持っており、連結すると gallery の本文まで
3 列に割れる（実際に起きた）。器を `.gallery` にすれば、雛形のページレイアウト用セレクタ
（`main` / `#bar` / `#q-pane` / `#fn-pane`）がどれも一致しない。
持ち込みたいのは色トークンと文字組だけで、ページの骨格ではない。
