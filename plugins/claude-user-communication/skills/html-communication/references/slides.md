# スライドの作成と操作

report を、素の HTML・CSS・JavaScript による固定 16:9 のスライドとして生成する。
Marp、Reveal.js、追加フォントは使わない。共通の生成器が操作を組み込み、資料ごとにスクリプトを作らない。

## 構成する

- 1 枚につき主張を 1 つ置き、見出し、短い説明、図や比較表で優先順位を付ける。
  長い文章をそのまま切って並べず、発表時に見せる単位へ組み直す。
- 根拠の長い説明やコードは共通の詳細パネルへ分ける。スライド自体には結論と、詳細を開けると分かる操作を残す。
- 狭い画面でも初期表示は固定 16:9 の配置を保つ。画面幅に応じて縦読みに自動で切り替えない。
  文章として読む操作は、閲覧者が「読む表示」へ切り替えて選ぶ。
- 内容が固定の枠からはみ出す場合は、枚数を増やすか、根拠を詳細へ移す。
  はみ出したまま隠したり、文字だけを縮めて詰め込んだりしない。

why: スライドは配置と表示順序を含めて説明する資料であり、画面幅で配置が変わると説明のまとまりが変わる。
長文が主になる場合は通常のレポートにする。

## 生成元 JSON

[ページの生成元 JSON の書式](./page-format.md)を使い、`type` を `report`、`presentation` を `slides` にする。
`format` は書式の版なので `1` のままにする。

- `title`、`context`、`summary` が表紙になる。前提と要点を短くする。
- `sections` の `explain` 1 件が 1 枚になる。見出しはその枚の主張、`blocks` は表示する説明と図表にする。
- `reference` と `generation` を書く場合は、それぞれ付録のスライドになる。
- 図表・コード・脚注・補足・詳細パネルは既存のブロックを使う。必要なブロックの参照だけ追加で読む。
- `form` にはスライド形式を指定しない。設問を含む確認は通常の確認フォームで行う。

```json
{
  "format": 1,
  "file": "sample-r001",
  "type": "report",
  "presentation": "slides",
  "title": "検証結果を次の判断へつなぐ",
  "project": "sample",
  "context": ["比較した結果と、次に確かめる条件を共有する。"],
  "summary": ["条件を揃えた再検証へ進む。"],
  "sections": [
    {
      "kind": "explain",
      "heading": "結果を先に示し、根拠を必要なときに開く",
      "blocks": [
        "概要には判断に必要な結論を置く。",
        { "ul": ["検証の条件を揃える。"], "step": 1 },
        { "ul": ["差が残る条件を次に調べる。"], "step": 2 }
      ]
    }
  ]
}
```

### 要点を順に出す

発表など、説明する順序が必要な枚だけ、ブロックへ `step` を指定する。
通常の資料では指定せず全要点を最初から見せる。

- `step` は `1` から昇順で連続する正整数にする。枚ごとに `1` から始める。
- 同じ数のブロックは同時に現れる。指定しないブロックは常時表示される。
- 箇条書きの項目ごとに順番を変えるなら、箇条書きのブロックを分ける。
- 詳細パネルの中身に段階表示を付けない。開いた根拠は全文を読めるようにする。

why: 表示待ちを設けるのは説明順序を示すためであり、普段の読書で情報を隠すためではない。

## 共通の操作

- 前後のボタンと矢印キーでページを送る。「次へ」は未表示の要点があるときは次の段階を出し、
  全要点を出した後に次の枚へ進む。
- ページを送ると短い遷移を使う。「静止表示」に切り替えると演出を止め、全要点を表示する。
  端末の「動きを減らす」設定でも同じように演出を止め、表示待ちを残さない。
- 「読む表示」へ切り替えると全文を縦に読む。固定配置へ戻せる。
- 詳細パネル、画像の拡大、図の補足、脚注の全文表示は共通操作を使う。
  パネルの中や入力欄を操作している間は、ページ送りで操作を奪わない。
- JavaScript が無効なときと印刷時には全枚・全要点・詳細の全文を出す。
- 発表者ノート、自動再生、台本付きの自動操作デモは作らない。

操作は共通テンプレートの責務であり、固定の操作例をギャラリーへ追加しない。
内容に応じて選べる図や比較表の表現は、通常の資料と同じくギャラリーから選ぶ。

## 生成と検証

配置先、発番、組み立て、index 登録、状態管理は [ページの生成と一覧の運用](./common-workflow.md)に従う。
スライドも単一 HTML に CSS・JavaScript・画像を含め、外部 CDN やフォントへ依存しない。
スライドを実装するための追加依存は不要である。

[提示前の検査とレビュー](./verification.md)に加えて、固定の枠への収まり、表や図の重なり、
最初と最後の移動、実ボタンとキー、表示順序、詳細からの復帰、手動の表示切り替えを確認する。
明暗と狭い画面の両方で描画し、狭い画面でも初期表示が 16:9 を保つことを確かめる。
はみ出しがあれば資料の構成を直し、確認し直してから提示する。

Playwright と Chromium が導入済みなら、固定の枠への収まりを次のスクリプトでも検査できる。
`{SKILL_DIR}` は `SKILL.md` があるディレクトリの絶対パスに置き換える。

```sh
node "{SKILL_DIR}/scripts/check-slides.mjs" <ページの絶対パス>
```

Playwright が別の場所にあれば、`HTML_COMMUNICATION_PLAYWRIGHT_MODULE` にその `index.mjs` の絶対パスを渡す。
このスクリプトを使えない場合は、利用できるブラウザで同じ枠への収まりを確認する。
導入済みでない Playwright を自動でインストールしない。
