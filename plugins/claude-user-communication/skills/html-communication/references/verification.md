# 提示前の検査とレビュー

`{SKILL_DIR}` は `SKILL.md` がある skill ディレクトリの絶対パスを表す。
この参照ファイルがある `references/` ではない。コマンド内では実際のパスに置き換える。

## 提示前の機械検査

ページを生成・改稿したら、提示前のレビューより前に検査スクリプトを実行する。

```sh
"{SKILL_DIR}/scripts/validate-page.sh" <ページのパス>
```

- 4 層（html-validate / linkinator --check-fragments / 雛形固有の自作検査 + onclick grep /
  生成元 JSON の検査 `check-source.mjs`）を一括実行し、指摘を JSON で stdout に集約する。
  `total` が 0 になるまで JSON を直し、組み立て直して再実行する
- 雛形固有の検査は、`<style data-scope="figures">` 内の `var(--名前)` を、共通ページ template と
  同じ図の CSS にある定義名へ照合する。定義が無くても `var(--名前, fallback)` のように
  直接の fallback があれば許可する。セレクタの適用範囲、循環参照、fallback 内の参照、
  代入後の値の妥当性、escape または非 ASCII 文字を含む property 名はこの検査では保証しない
- 検査対象はそのセッションで生成・改稿したページだけ。過去ページには旧雛形由来の指摘が
  残っているため、一括適用しない
- `check-source.mjs` は同じディレクトリの `src/{語幹}.json` を見つけて、書式・参照の解決・
  文字列へのタグの混入・番号の直書き・図の対応・D2 の図・パターン集の CSS・
  閲覧用 HTML との食い違い（`stale-html`）の 8 つを見る。
  `stale-html` は JSON を直したあと組み立てていないときに出る。
  D2 の図の検査は、`.d2` を直したあと描画し直していない図と、幅が 560px を超える図を指摘する
  脚注と補足の初出順は組み立てが採番するので、`ref-order` は落ちない
- 「一覧に戻る」リンク（`./index.html`）の解決に同ディレクトリの index.html が要る。
  配信ディレクトリ内のファイルパスで実行する
- npx のキャッシュがあればオフラインで動く。1 ページ約 7 秒（初回のみダウンロードで + 数秒）
- Exit: 0 = 指摘なし、1 = 指摘あり、2 = 前提条件エラー（node / npx が無い等）
- 検査を通したら、ターミナルに書く内容を URL と問いだけに絞る。
  申し送りを書きたくなったらページへ足して、検査からやり直す

## 提示前のレビュー

提示前に agent を 2 本、順に回す。先に `sentence-reviewer`、次に `page-reviewer`。
`sentence-reviewer` は form と report の両方に回す。`page-reviewer` は設問を含む form だけに回し、
設問の無い報告には回さない。

- Claude Code では同梱の名前付き agent を起動する。両 agent は plugin の `references/` に置いた
  判定手順を読む
- Codex では各レビュー用に `fork_turns: "none"` で子 agent を起動し、`{SKILL_DIR}` の二階層上にある plugin の
  `references/sentence-review.md` または `references/page-review.md` の絶対パスを渡す。
  文のレビューには、この会話の履歴や議題の説明を渡さず、生成元と判定手順だけを渡す。
  内容レビューには下記の一次情報も渡す。子 agent には対象ファイルを編集させない
- 必要な子 agent を利用できない場合、そのレビューを実施済みと扱わない。
  提示前に未実施のレビューと理由をユーザーへ伝え、続行するか確認する

### sentence-reviewer（文の意味）

渡すのは生成元 JSON（`src/{語幹}.json`）の絶対パスと、図があれば `src/{語幹}.figures.html` と
D2 の原文（`src/{語幹}.{図の id}.d2`）の絶対パスだけ。
D2 の SVG は渡さない（base64 のフォントを含み、図の文字列は原文で読める）。
閲覧用 HTML は渡さない（CSS と script は判定に使わない。JSON を持たない旧ページだけ HTML を渡す）。
一次情報・議題の説明・元ドキュメントを渡さない。
規範ファイル（user global rule の日本語規範など）があれば任意で渡してよく、渡すと指摘に条項が付く。無くても動く。

書き手は自分が何を言いたかったかを知っているので、書かれていない部分を頭の中で補って読む。
背景を知る読み手も同じ。文脈を持たない読み手だけが、意味の取れない文を検出できる。

agent は文ごとに「誰が何をどうするか」「何が事実として主張され、何を確かめれば真偽が決まるか」を
取り出せるかで判定し、取り出せない文と、取り出せるが条件・動作主が文の外にしか無い文を分けて挙げる。
あわせて、ページ内に定義の無い呼び名（汎用名詞 + 数字、その場で振った記号、名前として使われた汎用語）と
用語の揺れを挙げる。ユーザーの語か作成側が作った語かは agent には分からないので、
ユーザーの発言に遡れるかは呼び出し元が判断する。
直し方は書かない。手順と判定基準は [文の提示前レビュー](../../../references/sentence-review.md) にある。

### page-reviewer（一次情報との突合）

呼び出すときに渡すもの。

- 生成元 JSON（`src/{語幹}.json`）の絶対パスと、図があれば `src/{語幹}.figures.html` と
  D2 の原文（`src/{語幹}.{図の id}.d2`）の絶対パス（JSON を持たない旧ページだけ HTML の絶対パス）
- 一次情報の所在（decision-record・設計ドキュメント・実装・過去の回答フォーム）
- そのページが何を決めるためのものか

agent が見るのは、一次情報との突合（捏造と誤引用）と、推奨・選択肢集合の妥当性と、
構成と設問の自立性（設問の節だけで答えられるか、脚注と補足の使い分け）だけ。
文言・マークアップは上の機械検査と [本文の規範](./writing.md) が、文の意味と造語は `sentence-reviewer` が持つので見ない。
手順と観点は [内容の提示前レビュー](../../../references/page-review.md) にある。

### 反復の終了条件

**指摘 0 件まで繰り返さない。**

- `sentence-reviewer`: 指摘があれば直して **もう 1 度だけ** 回す。2 回目の指摘はそのラウンドで直して終わる
- `page-reviewer`: 推奨または選択肢集合を変える指摘が出たら、直して **もう 1 度だけ** 回す。
  文言・マークアップの指摘は、そのラウンドで直して終わる。再ラウンドしない
- `sentence-reviewer` のラウンドを終えてから `page-reviewer` を回す。`page-reviewer` は最終の文を読む
- レビュー実行中は対象ファイルを編集しない。agent は起動時点の版を読む

### この形にした理由

実測（2026-08-18、idea-hub の ih-f007）で、4 facet 2 ラウンド 8 本が指摘 133 件・
subagent トークン 828k・1 ラウンド約 14 分を使った。内訳は設計妥当性 25 件 / 165k、
内容整合 23 件 / 264k、情報デザイン 27 件 / 280k、clarity 58 件 / 118k。

- 推奨や選択肢集合を変えた指摘は、設計妥当性と内容整合からしか出ていない
- 情報デザインと clarity は全体の 48% のトークンを使い、判断を変えた指摘が 0 件
- 情報デザインの指摘の多くは雛形自身の欠陥で、ページごとに再発見されていた（雛形を直した）
- clarity の指摘の大半は機械判定できる形をしていた（機械検査へ移した）

統合後を同じ規模のページ（ccm-f026、設問 2 件・図 2 点）で 1 本回して **84.8k トークン**。
統合前の 2 facet 合計 429k に対して約 80% 減で、一次情報の重複読みが消えた分が出ている。
指摘の質は落ちていない。この 1 本が、旧 4 facet の 2 ラウンドが見逃していた
「推奨の根拠にした前例が当時の実文に存在しない」を `git show` で確かめて出した。

文の意味と造語（ページ内に定義の無い呼び名）は sentence-reviewer が持つ。
それ以外の clarity は機械検査と作成規範が持つ。
機械検査が拾えるのは識別子・文長・参照マーカーまでで、造語も文の意味も語形からは判定できない。
日本語テキストの観点を sentence-reviewer に、構成と設問の自立性を page-reviewer に寄せる分担は
PR #20 のレビューで決めた（2026-09-08）。

sentence-reviewer は 2026-09-07 に足した。clarity facet を外した判断の根拠は「文が分かるか」を判定させる形の実測で、
「誰が何をどうするか」を取り出せるかを課す形は測っていなかった。
機械検査と page-reviewer を通ったページ（efso-idp の eidp-f032）で subagent に取り出しを課すと、
opus は 30 文、sonnet は 1〜2 文を挙げた。model を opus にするのはこの差による。
