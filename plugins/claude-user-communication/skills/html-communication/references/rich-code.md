# コード・差分・呼び出しツリー

コードを行単位で説明し、変更前後や処理のつながりを示すときに使う。
生成元 JSON のブロックで指定し、表示と操作は共通実装に任せる。

## 表示と回答操作を選ぶ

- 原文を短く載せるだけなら `pre`、行番号や注釈を付けるなら `code` を使う。
- コードの変更前後を比べるなら `diff` を使う。文章の改稿を示す表現とは分ける。
- 関数の呼び出し関係を示すなら `calls` を使う。作成者が確認した静的な関係を書き、実行時のスタックトレースとして扱わない。
- 呼び出し関係を読むだけなら `interaction` を省略する。通常の `report` と `form` の両方で使える。
- カードへの修正指示を求める `form` には `interaction: "propose"`、変更の採否を求める `form` には `interaction: "reject"` を指定する。

自由記述の指示と採否を分ける。指示を書いただけで変更を除くと、修正して採用したい内容まで棄却される。
任意のコード行や図の一部へコメントを付ける操作、コードの直接編集、資料全体の変更サマリーは、この書式に含めない。

## 行番号と右側の注釈

```json
{ "code": {
  "id": "reservation-code", "title": "送信予約を保存する",
  "file": "src/schedule.ts", "language": "typescript", "startLine": 40,
  "text": "export async function reserve(message) {\n  await queue.save(message);\n}",
  "annotations": [
    { "line": 41, "title": "保存する時点", "text": "送信前に予約を保存する。" }
  ]
} }
```

`id` と `text` は必須。`id` は英字で始まる英数字・ハイフンで、ページ内のブロックごとに一意にする。
`title`、`file`、`language`、`startLine`、`annotations` は任意。
`startLine` は 1 以上の整数で、省略すると 1 行目から番号を付ける。
注釈の `line` は表示する絶対行番号と一致させ、同じ行へ複数の注釈を置かない。
注釈の `title` と `text` は空でない文字列にする。本文の記法と脚注参照を使える。

注釈はボタンからコード右側へ開き、狭い画面では右側からコードに重なる。
コード行の間には説明を挿入しない。閉じるボタン、Escape キー、外側の操作で閉じる。
長い行は横スクロールで読み、「折り返す」で表示を切り替える。

`text` は原文の文字列として渡し、HTML のタグに変換しない。
色分けは JavaScript・TypeScript・JSON・Python・shell の文字列、コメント、数値、限定したキーワードに対応する。
構文解析やコードの妥当性検査ではない。その他の言語も原文と行番号を表示する。

## 左右比較と統合表示の差分

```json
{ "diff": {
  "id": "reservation-diff", "title": "即時送信から予約保存へ変える",
  "file": "src/schedule.ts", "beforeStart": 40, "afterStart": 40,
  "before": "await send(message);",
  "after": "await queue.save(message);"
} }
```

`id`、`before`、`after` は必須。`title`、`file`、`beforeStart`、`afterStart` は任意。
変更前後には比較する範囲の全文を渡す。unified diff のパッチ文字列は渡さない。
行番号の開始位置は 1 以上の整数で、省略すると双方とも 1 から始まる。
追加だけを示すときは `before` を空文字、削除だけなら `after` を空文字にする。

初期表示は左右比較。「一列で比較」で削除・追加を一列に並べる統合表示へ切り替える。
行番号と追加・削除の記号を出し、対応する変更行では変わった語も強調する。
長い行の横スクロールと折り返しを、コードと同じ操作で切り替えられる。

## 枝線と関数カード

```json
{ "calls": {
  "id": "schedule-calls", "title": "予約してから送信する処理",
  "interaction": "propose",
  "nodes": [{
    "id": "submit", "name": "submitMessage()", "status": "existing",
    "file": "src/submit.ts", "line": 12,
    "summary": "メッセージを受け取る。",
    "children": [{
      "id": "reserve", "name": "reserveMessage()", "status": "modified",
      "file": "src/schedule.ts", "line": 40,
      "summary": "送信予定時刻と本文を保存する。",
      "detail": { "title": "予約保存のコード", "blocks": [
        { "code": { "id": "reserve-detail", "startLine": 40,
          "text": "await queue.save(message);" } }
      ] }
    }]
  }]
} }
```

`calls` の `id`、`title`、空でない `nodes` は必須。
カードの `id`、`name`、`status` も必須。カードの `id` は、そのツリー内で一意にする。
同じ関数を複数の場所に出す場合も、カードごとに異なる `id` を付ける。

| `status` | カードの役割 |
| --- | --- |
| `existing` | 背景として示す既存実装 |
| `added` | 提案する追加 |
| `modified` | 提案する変更 |
| `removed` | 提案する削除 |

`file`、`line`、`summary`、`detail`、`children` は任意。
`line` は 1 以上の整数にする。`children` を指定するときは空でない配列にする。
`detail` は空でない `title` と `blocks` を持ち、共通の「コードを見る」リンクを表示する。
詳細には `code` と `diff` を置ける。`calls` を詳細の中へ入れない。

`children` には呼び出し先を置く。枝線とカードの説明が、実装で確認した関係を表すようにする。
棄却の影響もこの親子関係に従うので、互いに独立した変更は別の枝へ分ける。
`file` は実際の変更先を指定する。ファイル数は同じパスを重複して数えず、`existing` の参照先は含めない。

## カードへの修正提案

`interaction: "propose"` では、変更カードに「この変更に修正提案」、
既存カードに「この既存実装へ変更提案」を表示する。
押すとその場に自由記述欄が開く。既存カードが背景説明のために置かれていても、変更を提案できる。
通常の設問を少なくとも 1 問持つフォームに、カードごとの補助回答として追加する。
カードへの指示だけを集める設問なしフォームは、この書式では作れない。
空の入力は回答へ含めない。入力の有無で変更件数とファイル数は減らさない。

## 変更の棄却と復元

`interaction: "reject"` では、追加・変更・削除のカードを棄却し、復元できる。
既存カードは採否の対象にしない。棄却には任意の補足を書ける。
親を棄却すると配下も対象外になり、親を復元すると配下自身の選択が戻る。
残る変更件数と、残る変更が触るファイル数を表示する。
同じファイルの別の変更が残るなら、そのファイルは集計に残る。

## 下書きと回答への受け渡し

入力、棄却状態、補足は設問の選択とともに下書きへ保存し、回答コピーへ含める。
回答へはツリーとカードの `id` を渡すので、提示後に回答対象の `id` を付け替えない。
対象を取り違えず受領するため、同じ内容の修正版でも識別子を保つ。

コピーには `- 対象別提案:` に続けて空白と JSON 配列が入る。
各項目は `tree`、`node`、`action`、`text` を持つ。
`action` は変更への修正提案が `revise`、既存実装への変更提案が `change`、棄却が `reject`。
棄却には影響する配下のカードの `id` を `affected` として付ける。
自由記述の改行は JSON の文字列としてエスケープされ、指示の原文を保つ。

受領は [フォーム回答の受領](./answer-receipt.md) に従う。
受領済みページでは入力と採否を変更できない状態で示す。
コード表示自体は読み取り専用で、提案文がコードへ自動適用されることはない。
