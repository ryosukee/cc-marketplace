# 詳細・階層・補足・脚注の操作

`{SKILL_DIR}` は `SKILL.md` がある skill ディレクトリの絶対パスを表す。
この参照ファイルがある `references/` ではない。コマンド内では実際のパスに置き換える。

## 用語の説明は補足 pane へ出す

用語の説明は本文に置かず、補足（JSON の `supplements`）へ出して本文から参照マーカーで飛ばす。
定義を要るのは知らない読者だけで、知っている読者には本文を分断する障害物になる。
3 pane では開いた補足 pane が本文と同時に見えるので、飛ばずに読める。

- 冒頭に用語集の節を作らない。語が初めて判断に関わる位置で参照マーカーを置く
- 1 語 1 補足。1 補足に複数の語を詰めない
- 説明は 1〜3 文。何であるかと、その判断にどう効くかまでを書く
- 短い定義を並べるときは `※ 語 = 定義` の形を 1 行ずつ使い、語だけを太字にする。
  補足 pane の中で使う書き方で、本文には置かない
- 1 つの節で 3 語を超えるなら、説明の順序か構成が間違っている。語を減らすか節を分ける

**識別子・番号つきの語は、必ず補足に実体を書く。**
規範 ID（`DG14`）、フェーズ番号（`T4`）、フォーム番号（`f017`）、PR 番号、
独自の分類コードが対象。番号だけでは何を指すか分からず、
読者は decision-record を開かないと判定できない。ページ内で完結させる。

本文での呼び方は[呼び方を揃える](./writing.md#呼び方を揃える)に従う。

```json
"blocks": ["現行の DG14[^dg14] は…"],
"supplements": {
  "dg14": "**DG14** = 執筆規範の条項番号。現行の実文は「修飾語は係り先の直前に置き、スコープが曖昧なら鉤括弧で括る」。鉤括弧の部分は 2026-08-15 に廃止が決まっている。"
}
```

判定基準: その説明を消したとき、直後の表や設問が読めなくなるか。
なるなら補足に置く。ならないならその語は本文に要らない。

## 脚注は双方向のページ内リンクにする

出典・実測値・根拠を脚注へ逃がしたら、本文の参照記号と脚注を相互にリンクする。
番号だけを振って飛べない状態にしない。

- 本文側: 文の中に `[^キー]` を置く。組み立てが `<sup>` の参照マーカーと id
  （`fnref-{番号}-{同一脚注内の連番}`）を出し、脚注へ飛ばす
- 脚注側: `footnotes` にキーと本文を書く。組み立てが id `fn-{番号}` を振り、先頭の番号を参照元へのリンクにし、
  末尾に戻りリンク（`↩`）を置く
- 同じ脚注を複数箇所から参照してよい。組み立てが参照ごとに別の id を振り、
  戻りリンクを参照の数だけ並べる（`↩1` `↩2`）。戻り先が 1 つに潰れると往復できない
- `scroll-margin-top`（飛んだ先がビューポート端に貼りつかない）と `:target` の強調（番号だけでは着地点が分からない）は
  雛形の CSS が持つ
- 共通の JavaScript が参照マーカーの操作を受け、参照元で全文を表示する。
  脚注欄を開いて読む場合も本文の読み位置を保つ。JavaScript が動かない環境ではアンカーの既定の動きになる

```json
"rows": [["載る[^measure]", "…"]],
"footnotes": { "measure": "実測（2026-07-27）: …" }
```

参照の解決（キーの定義漏れ / 参照漏れ / 両方に同じキー）は `check-source.mjs` が、
生成した HTML の対応（リンク切れ・id の重複）は[提示前の機械検査](./verification.md#提示前の機械検査) の残りの層が検査する。

## 詳細パネル

判断材料の要点は本文に置き、読み手が必要に応じて読む詳細を `detail` ブロックへ分ける。
`label` に何を開くか分かる呼称、`title` に開いたパネルの題名、`blocks` に詳細を書く。

```json
{ "detail": { "label": "検証条件の詳細を開く", "title": "検証条件",
  "blocks": ["条件ごとの違いを説明する。"] } }
```

- `label` と `title` は空でない文字列。`title` は通常のインライン記法を使える。
  `label` にリンク記法や脚注参照を入れない。
  起動点の中に別の操作対象を入れると、何を開くかが曖昧になる。
- `blocks` は空でない通常のブロック配列。詳細の中に別の `detail` を置かない。
  詳細の中の `tree` を経由する場合も同じ。重ねて開くパネルの入れ子を作らない。
- `detail` オブジェクトのキーは `label`・`title`・`blocks` だけにする。
- リンクから本文に重なる広いパネルを開く。閉じる操作とキーボード操作は共通テンプレートが持つ。
  印刷と JavaScript が動かない環境でも詳細を読める構造にする。

## 階層を1段ずつ開く

親子関係を概要から順に読むときは `tree` ブロックを使う。
各項目の `text` はその項目が何か分かる短い文、`blocks` は項目の説明、`children` は子項目にする。

```json
{ "tree": [{ "text": "ページの生成", "blocks": ["JSON からページを組み立てる。"],
  "children": [{ "text": "元データの検査", "blocks": ["参照と書式を確かめる。"] }] }] }
```

- `tree` と `children` は空でない項目配列。項目の `text` は空でない文字列で、通常のインライン記法を使える。
- `blocks` と `children` は任意。`blocks` は通常のブロック配列で、空配列でもよい。
  項目のキーは `text`・`blocks`・`children` だけにする。
- 子を持つ項目を開くと、その1段下を出す。子孫をまとめて展開しない。
  説明も子項目もない項目は開閉しない。
- ツリーの説明には詳細パネルを置けるが、詳細パネルの中では別の詳細パネルを作らない。
  単に長い文章を隠すためには使わず、親子関係をたどる内容に使う。

## 図のそばで補足を開く

図の補足は `fig.notes` に書く。figures ファイルの図にも D2 の図にも使える。
`custom` 図には指定できない。

```json
{ "fig": { "id": "flow", "caption": "検査から提示までの流れ",
  "notes": [{ "label": "検査の補足", "text": "検査した条件を説明する。" }] } }
```

- `notes` は空でない配列で、各項目は `label` と `text` だけを持つ。どちらも空でない文字列。
  `text` は通常のインライン記法を使い、ブロック配列にしない。
  `label` にリンク記法や脚注参照を入れない。
- ホバーまたはキーボードフォーカスで補足を出し、クリックで表示を固定する。
  ホバー中の起動点にはクリックで固定できることを示す。
  個別の図へこの操作を行う JavaScript を書かない。
- 図の中の対象点や独立 Viewer の要素へ自動で補足を結び付けない。
  要素ごとの位置を説明する必要がある場合は、図の内容と補足の対象を明示する。

## 参照元で脚注の全文を読む

`footnotes` と `supplements` の本文は、参照マーカーの位置で全文を読めるようにする。
脚注欄は初期状態で閉じ、必要なときに共通のトグルで開く。
本文の読み位置を保ったまま補足を読める操作を共通テンプレートが持つ。
JavaScript が動かない場合は、従来の双方向アンカーで本文と脚注を往復する。

図の補足と脚注・補足のプレビューは同じ操作を使う。
ホバー・フォーカスで一時表示し、プレビュー内へポインターを移して読める。
起動点やプレビュー本文のクリック、Enter・Space、タッチの1回のタップで表示を固定する。
外側のクリック、Esc、閉じる操作で閉じる。
キーボードで固定したときは閉じる操作へフォーカスを移し、閉じたら起動点へ戻す。
印刷時は詳細本文を元の位置に戻し、階層と図の補足をすべて開いて読めるようにする。
