# 図の生成と描画確認

`{SKILL_DIR}` は `SKILL.md` がある skill ディレクトリの絶対パスを表す。
この参照ファイルがある `references/` ではない。コマンド内では実際のパスに置き換える。

- **図の中は色を自由に使ってよい。** 条件は 3 つ
    - 何の色かを凡例で示す
    - 色だけに意味を載せず、字面か形を併記する（WCAG 1.4.1）
    - その色を図の外（地の文・表・設問・UI）へ持ち出さない

- 図は JSON の `fig` ブロックで書き、markup は `src/{語幹}.figures.html` の `<template data-fig>` に置く。
  組み立てが雛形の `.fig` で包み、番号付きのキャプション（`.cap`）を図の下に出す。
  字の大きさと色は表の `caption` と揃う。JSON の `caption` には何の図かだけを書く。
  `.fig` 内の `<img>` は雛形がクリックと Enter / Space で開く拡大 viewer の対象にする。
  viewer は原寸画像を保ち、画面より大きい画像は内部スクロールで確認できる。
  ページ固有の figures ファイルへ拡大用の JavaScript を追加しない
- **図の CSS は本文の CSS と分ける。** figures ファイルの `<style data-scope="figures">` に
  図のための CSS だけを入れる。組み立てが雛形の `<style>` の後ろに置く。
  色役割とフォント段の制限は、この `style` の中には適用しない。
  機械検査は色役割とフォント段を対象から外すが、fallback 無しで参照する未定義の
  CSS custom property はエラーにする
- **図の生成手段は、本文へ埋め込むか、独立した Viewer で見せるかによって選ぶ。**
  既存パターンで表せる図はパターン集を使う。独自の図を本文へ埋め込む場合は Tailwind CLI を使う。
  読み手が線をたどって読む図（隣り合わない要素を結ぶ線、線の合流・交差、自分へ戻る線があるもの）と、
  シーケンス図・ER 図・クラス図は、パターン集の README の「図を D2 で組む」の条件を満たせば D2 で描き、
  img として埋め込む。
  architecture、workflow、sequence、data flow、lifecycle / state diagram のいずれかで、
  pan / zoom、探索、trace、export に価値があり、現在の skill 一覧で Archify が利用できる場合は、
  Archify を起動して検証済みの独立 HTML Viewer を作る。詳細な使い分けは
  [見せ方のパターン集](./patterns/README.md) にある
    - Archify を自動で導入しない。利用できなければ、既存パターンまたは Tailwind のインライン図へ戻す
    - HTML レポートも必要なら、本文には要点だけを置き、独立 Viewer へのリンクを置く。
      Archify の成果物は `fig`、パターン集、html-communication のサブページには含めず、
      Archify が検証・確定した HTML を後から編集しない
- D2 の図は、原文を `src/{語幹}.{図の id}.d2` に書き、
  `node "{SKILL_DIR}/scripts/render-d2.mjs" <src/{語幹}.json>` で SVG に描画してから組み立てる。
  図の要点は本文に文字で書く。img の中の文字はページ内検索にかからず、支援技術にも読まれない。
  手順と条件は [見せ方のパターン集](./patterns/README.md) にある
- 独自の図は Tailwind CLI で組む。外部 CDN は使えないので、生成時に CLI を回して
  使ったクラスだけの CSS を出し、figures ファイルの `<style data-scope="figures">` へ貼り込む。
  手順は [見せ方のパターン集](./patterns/README.md) にある。
  リセット（preflight）は読み込まない。読み込むと雛形の表・見出し・段落の作りが消える

## 提示前の図の描画確認

新規作成または変更した図を含むページは、機械検査の後に実際のブラウザで描画する。
ライト表示とダーク表示を、横幅 1440 px と 390 px のそれぞれで開き、4 枚のスクリーンショットを撮る。

4 条件のすべてで、変更した図の全体が写るスクリーンショットを確認する。図の境界線が表示されること、
境界線と背景が同化しないこと、要素が切れたり横へ溢れたりしないこと、文字を読めることを目視する。
スクリーンショットは検査用の一時ファイルとして扱い、
配信ディレクトリと repo には保存しない。

1 条件でも欠陥があればページを提示しない。レビュー後の修正を含め、生成元 JSON・figures ファイル・D2 の原文のいずれかを修正したら、
ページの再組み立て、機械検査、4 条件の描画確認を最初からやり直す。
ブラウザの描画またはスクリーンショットを利用できない場合は、描画確認を実施済みと扱わず、
未実施の条件と理由をユーザーへ伝えて続行するか確認する。
